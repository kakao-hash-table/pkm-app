# 자동화 원칙 — 맡기고 손을 뗄 수 있게

pkm 플러그인이 사람 대신 일할 때(찾기·작성·제출·연락) 지키는 규칙이다. 목적은 하나 — 사용자가 안심하고 일을 맡기고 자기 시간을 돌려받는 것. 그래서 똑똑함보다 **신뢰**가 먼저다.
새 플러그인·워크플로우를 만들거나 고칠 때 아래 항목마다 점검한다(결정에 `A1`~`A6`을 붙인다).

## A1. 'HOW'가 아니라 'WHAT'만 묻는다
- 사용자는 목표만 던진다. 방법·탐색·순서는 플러그인이 정한다. "어떻게 할까요?", "어느 안으로 할까요?", "다시 할까요?"처럼 방법을 되묻지 않는다.
- 물어도 되는 것은 **사용자만 아는 사실**(주소, 조합원 여부 같은 내 정보·내 선택)뿐이다.
- 물을 것이 있으면 **한 번에 모아서** 묻는다. 하나씩 묻고 기다리지 않는다. 답하면 묻지 않고 이어서 끝까지 간다.
- 받은 답은 기억해서 다음에는 묻지 않는다.
- 실패하면 먼저 스스로 한 번 더 해 본다. 그래도 안 되면 무엇이 막혔는지(사실)와, 사용자가 할 수 있는 한 가지만 보인다.

## A2. 되돌릴 수 없는 일에는 칼 같은 경계를 둔다
- **알아서 끝까지**: 찾기, 비교, 요강 읽기, 초안·안 만들기, 양식 채우기, 미리 보기 — 되돌릴 수 있는 일은 묻지 않는다.
- **딱 한 번 승인**: 외부로 나가거나 사용자에게 귀속되는 일 — 제출, 메일 발송, 결제, 계정 정보 변경, 동의 표시.
  - 승인은 한 번이면 된다. 미리 켜 둔 스위치(예: 완전 자동화)는 그 한 번의 승인이다 — 켜져 있으면 다시 묻지 않는다. 꺼져 있으면 실행 직전에 한 번 묻는다.
  - 같은 일을 두 번 하게 될 위험(지난 제출이 됐는지 모름)이 있을 때만 다시 확인한다.
- 선택 동의(홍보·마케팅 수신)처럼 목표에 필요 없는 일은 승인과 무관하게 하지 않는다.

## A3. 사용자의 행동을 극단적으로 압축한다
- 사람 손이 꼭 필요할 때는 가장 짧은 한 번으로 만든다: 입력창 한 번, 버튼 하나, 화면 하나.
- 화면에 보이는 것은 **지금 내가 할 일**뿐이다. 이미 자동으로 끝난 것은 접어 두고(펼치면 볼 수 있게), 다 끝난 것은 다른 탭으로 옮긴다.
- 기다리다 꺼지는 구조를 만들지 않는다. 사람의 답을 기다릴 때는 일을 멈춰 두고, 답이 오면 그때 다시 켠다.
- 로그인·본인 인증처럼 사람이 해야 하는 일은 한 번 해 두면 남게 하고, 그 화면만 넘긴다. (비밀번호를 대신 넣거나 사이트의 봇 판정을 우회하지 않는다 — 신뢰가 먼저다.)

## A4. 말이 아니라 증거로 알린다
- "냈어요"는 증거와 함께 말한다: 접수 번호, 완료 화면의 글, 응답 번호, 보낸 시각·받는 사람, 첨부 파일 이름.
- 증거가 없으면 "냈어요"라고 적지 않는다. "확인하지 못했어요"와 마지막으로 본 화면을 보인다.
- 사용자가 재확인하러 들어가지 않아도 되게, 증거는 결과 목록에서 바로 보인다.

## A5. 바깥 사람 앞에서는 체면을 지킨다(연락·발송)
- 사람에게 보내는 글·전화는 사용자의 얼굴이다. 이른 아침·늦은 밤처럼 민폐가 되는 때를 피한다.
- 누구를 대신하는지 투명하게 밝히고, 부탁받은 용건만 말한다. 위임받지 않은 개인 정보를 먼저 꺼내지 않는다.

## A6. 말을 부풀리지 않는다
- "갈 수도 있다"를 "가기로 했다"로, "제출을 눌렀다"를 "접수됐다"로 바꾸지 않는다. 조건부·불확실·확정을 구분해 그대로 전한다.
- AI가 추측한 것(요강 해석, 자격 판단)은 추측이라고 표시한다.
