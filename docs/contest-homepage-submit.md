# 공모전 신청 — 홈페이지 접수를 AI가 브라우저로 내기

상태: **만듦(contest-apply 0.7.0, 2026-11-11).** 아래 '지금 없는 것' 표의 네 가지를 모두 넣었다 — pkm-ai-server의 자리표시·사이트 제한·로그인 양식 지키기·도구 보강, pkm-app의 `browser(…)` 단계·넘겨받기·작업 화면 브라우저·브라우저 로그인, 플러그인의 [AI가 브라우저로 내기]. 로컬 가짜 주최 사이트에서 실제 Claude와 Chrome으로 읽기 → 채우기 → 필수 동의만 표시 → 제출 → 접수번호 확인까지 돌려 봤다(28초, 페이지에 숨긴 지시·로그인 상자·광고 링크는 따르지 않음). 실제 주최 사이트에는 아직 낸 적이 없다.

## 하려는 것
접수 방식이 '홈페이지'인 공모전에서, [제출 준비]의 제출 단계가 AI 에이전트에게 브라우저를 붙여 접수 화면을 열고 → 화면 요소를 읽고 → 칸을 채우고 → 제출까지 한다. 사이트마다 화면이 달라 미리 짠 규칙이 아니라 그때그때 읽고 판단한다.

## 사용자가 정한 것 (2026-11-11)
1. **순서**: `feat/browser`가 합쳐진 뒤에 올린다. 그 전에는 같은 파일을 건드리지 않는다.
2. **내 정보**: AI는 `{{이름}}` 같은 자리표시만 다루고, 실제 값은 이 컴퓨터의 프로그램이 넣는다. AI가 화면을 다시 읽을 때도 값은 자리표시로 가려서 보인다.
3. **마지막 제출**: 채우면 묻지 않고 제출한다(완전 자동화를 켜지 않아도).
4. 회원가입·로그인·본인 인증·캡차는 어느 경우든 사람에게 넘긴다(브라우저 기능의 `ask_user`).

## 지금 없는 것 — 합쳐진 뒤 만들 것
| 어디 | 무엇 |
|---|---|
| pkm-ai-server `browser.js` | 요청의 `agent.browser.vars`(자리표시 → 값)를 받아 ① `type`이 `{{이름}}`을 값으로 바꿔 넣고 ② `snapshot`·화면 글에서 그 값을 다시 자리표시로 가린다. 값은 작업 기록에 남기지 않는다 |
| pkm-app `server/runner.js` | 워크플로우의 에이전트 단계에 브라우저를 붙이는 문법(예: `agent(auto, browser)`)과 탭 키(`contest-apply:<공모전 id>`). 에이전트가 사람에게 넘긴 것(`BrowserHandoff`)을 실행의 '내 확인'으로 올리기 |
| pkm-app `web/index.html` | 작업 화면에서 그 실행의 브라우저 화면 보기·직접 누르기(지금은 채팅 창에만 있다) |
| `plugins/contest-apply` | `permissions.browser: true`, 제출 단계 뒤의 에이전트 단계와 프롬프트(`prompts/홈페이지.md`), 결과를 기록하는 스크립트 단계 |

## 흐름
1. 스크립트가 접수 주소·낼 안·뜻풀이·자리표시 목록과 값(`vars`)을 준비한다. 값은 에이전트 프롬프트에 넣지 않는다.
2. 에이전트: 접수 화면 열기 → `snapshot`으로 칸 읽기 → 폼 답과 같은 규칙으로 채우기(작품·뜻풀이는 글 그대로, 내 정보는 자리표시, 고르는 칸은 프롬프트의 '고르는 법') → 필수 동의는 설정대로 → 제출 → 완료 화면을 읽어 결과를 구조화해 돌려준다(`sent: yes | no | unknown`, 근거 한 줄, 완료 화면 글).
3. 스크립트가 결과를 기록한다. `unknown`이면 제출됐다고 적지 않고 사람에게 확인을 묻는다(두 번 내지 않게).

## 멈추고 사람에게 넘기는 경우
- 로그인·회원가입·본인 인증(휴대폰·아이핀)·캡차·결제
- 파일을 올려야 하는 칸(브라우저 도구에 파일 올리기가 없다)
- 접수 화면을 찾지 못함, 마감됨, 필수 칸에 넣을 내 정보가 없음
- 페이지가 다른 일을 시킴(다른 사이트 접속·프로그램 설치·관계없는 정보 요구) — 따르지 않고 알린다

## 확인 방법
- 가짜 접수 사이트(로컬 서버)로 채우기·제출·완료 판정·넘기기를 시험한다.
- 실제 주최 사이트에는 사용자가 [제출 준비]를 눌렀을 때만 낸다. 개발 중에 실제 접수 화면에 제출하지 않는다.
