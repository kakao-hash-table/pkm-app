레포 {활동.repo}의 노트 {활동.note}를 최신으로 고친다. 이 노트 파일 하나만 고친다.

로컬 클론: {활동.local} (비어 있으면 없음 — 그때는 GitHub에서 README·package.json을 읽는다)

찾을 것:
- 실행: 로컬에서 띄우는 법. 대표 명령은 package.json scripts에 실제로 있는 그대로 백틱으로(예: `pnpm dev`). 필요한 node 버전·환경 변수·프록시가 있으면 짧게.
- 배포: 환경(dev·sandbox·beta·real 등), 도구(Jenkins·GitHub Actions·ArgoCD·DKOS 등), 누가 언제 어떻게.
- 브랜치: 기본 브랜치, 작업 브랜치 이름 꼴, 어디로 머지하는지, 릴리즈·핫픽스.
- 스택, 지라 프로젝트 키, 한 줄 요약(무엇인지).

어디서 찾나(위에서부터):
1. 레포의 README·CONTRIBUTING·docs/, package.json, .nvmrc, .github/workflows, Jenkinsfile, Dockerfile, 배포 설정 폴더.
2. 사내 도구가 있으면 쓴다(토큰이 ~/.zshrc에 있어서 `zsh -ic '<명령>' 2>/dev/null`로 감싼다): `confluence search '<CQL>'`·`confluence get <URL>`(위키), `agit search <키워드>`·`agit thread <URL>`(아지트), `jira search '<JQL>'`(지라), `ghe get /repos/{활동.repo}/pulls state=closed per_page=100`(GitHub). 없으면 건너뛴다.
3. 문서에 없으면 사람들이 실제로 한 방식으로 정한다: 최근 머지된 PR의 head→base 브랜치, 머지 커밋 메시지, 태그, CI가 도는 브랜치, 배포 공지.
4. 문서와 실제가 다르면 실제로 쓰는 방식을 적는다(예: 문서는 release_*인데 PR은 releasefe_*). 근거는 `(관례: …, 문서는 …)`처럼 둘 다 짧게.

노트 쓰는 법:
- "# 내용" 아래 `- 키: 값` 줄 중 스택·실행·배포·브랜치·지라·확인만 고친다. 값은 한두 줄 안. 끝에 근거를 괄호로: 문서에 있으면 `(명시)`, 관례로 정했으면 `(관례: 최근 머지 PR 40건 중 37건 feature/* → develop)`. 모르면 비우지 말고 `모름 — 확인할 곳`.
- 실행 줄은 `` `명령` · 설명 `` 꼴로 시작한다(개발 도구 플러그인이 첫 백틱을 띄울 명령으로 읽는다). Spring Boot면 `./gradlew bootRun` 또는 `./gradlew bootRun --args=--spring.profiles.active=<프로필>`(따옴표 없이).
- 실행 줄에 이미 있는 `포트 8090`·`*.fedev.*` 도메인·프로필은 사람이 정한 것이니 지우지 않는다(개발 도구가 이 포트로 띄운다).
- 배포 파이프라인이 정말 없으면 `없음 — 이유`로 적는다(모름과 다르다).
- 확인은 오늘 날짜(YYYY-MM-DD).
- "# 한 줄 요약"이 비었거나 틀렸으면 고친다.
- "## 문서" 아래에 쓸모 있는 문서를 `- [제목](주소)`로 5개까지(있던 것은 두고 새로 찾은 것만 더한다).
- 레포·종류·로컬·활동 줄과 "## 메모" 아래는 건드리지 않는다(스크립트와 사람이 쓰는 칸).
- 프런트매터는 updated만 오늘로 바꾸고, sources에 실제로 읽은 위키·아지트 주소를 더한다. id는 절대 바꾸지 않는다.

하지 않는 것: 레포 파일 고치기, git fetch·checkout·pull·commit, 위키·지라·아지트·GitHub에 쓰기, 다른 노트 고치기, 지어내기.

마지막 답은 이렇게 짧게:
요약: 바꾼 줄과 근거 한두 문장
명시/관례: 실행 ○ · 배포 ○ · 브랜치 ○
확인할 것: 사람이 정해야 할 것(없으면 "없음")
