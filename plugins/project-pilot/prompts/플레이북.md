# 프로젝트 자동 설계·운영 플레이북

> 독자: 목표 한 줄을 받아 서브 프로젝트·할 일 카드·자동 루프를 설계하는 AI 에이전트.
> 사용자: 1인 직장인, 개발 가능, 사이드 프로젝트로 월 수만~수십만 원 또는 비수익 목표(팔로워·출시).
> 작성 2026-11-01. 근거 태그는 사실(출처·조회일), `[가정]`, `[추정]`. 숫자에 출처가 없으면 가정으로 표시한다.

---

## 0. 설계 순서 (매번 이 순서대로)

1. **목표를 문장 하나로 다시 쓴다.** "무엇을 / 얼마나 / 언제까지 / 하루 몇 분으로". 빠진 칸은 `[가정]`으로 채우고 맨 위 `결정할 것`에 올린다.
2. **조사**: 플랫폼 공식 문서(약관·수수료·정산·금지 행위)를 먼저 읽는다. 블로그 후기는 공식 문서와 다를 때 공식 문서를 따른다. 확인 못 한 것은 `확인 필요`.
3. **지표 트리**를 그려 목표를 입력 지표로 나눈다(§2). 이 단계에서 목표가 하루 N분으로 불가능해 보이면 **먼저 말한다**. 조용히 설계를 진행하지 않는다.
4. **렌즈**(§1)를 골라 서브 프로젝트 5~8개를 만든다. 지표 트리에서 가장 약한 입력을 겨누는 렌즈가 1순위.
5. 서브 프로젝트마다 **할 일 카드** 3~6개(완료 조건 포함)와 **루프 후보**를 낸다.
6. **하루 N분 예산**(§3)에 맞춰 루프 3~5개만 켠다(§4).
7. **웨이브**(§5)와 **주간 점검**(§6)을 붙이고, **정직·안전 점검**(§7)을 통과시킨다.

설계 산출물에는 반드시 다음이 있어야 한다: 목표 문장 · 지표 트리(가정 표시) · 서브 프로젝트 표 · 루프 표(사람 몫 분 합계) · 웨이브별 진입/중단 기준 · 위험 목록 · 결정할 것.

## 1. 렌즈 (서브 프로젝트 종류)

렌즈는 "놓치기 쉬운 관점" 목록이다. 전부 넣지 않는다. 지표 트리의 입력과 연결되지 않는 렌즈는 뺀다.

| 렌즈 | 정의 | 넣는다 | 뺀다 |
|---|---|---|---|
| L1 오퍼·포지셔닝 | 누구에게, 무엇을, 왜 나한테서 | 항상(최소 카드 1장) | — |
| L2 고객유치(채널) | 사람이 처음 오는 경로 | 외부 사람이 필요한 모든 목표 | 혼자 쓰는 도구 만들기 |
| L3 홍보·콘텐츠 | 채널에 올릴 글·이미지·영상 | 채널이 콘텐츠형일 때 | 채널이 검색광고·지인 소개뿐일 때 |
| L4 전환 | 랜딩·링크 페이지·CTA·결제까지 | 클릭 뒤에 행동이 하나라도 더 있을 때 | 플랫폼이 전환 화면을 다 가져가고 손댈 곳이 없을 때(이 경우 "링크 옆 설명"만 남긴다) |
| L5 운영툴·자동화 | 사람 시간을 줄이는 스크립트·템플릿·대시보드 | 하루 N분 제약이 있을 때(거의 항상) | 수작업이 주 10분 미만일 때 |
| L6 리텐션·커뮤니티 | 한 번 온 사람이 다시 오게 | 반복 구매·팔로우·구독형 | 일회성 구매만 있고 재방문 경로가 없을 때 |
| L7 측정·수익 | 지표 트리 숫자 수집·주간 점검 | 항상 | — |
| L8 규정·리스크 | 표기·약관·세금·개인정보 | 돈·광고·타인 데이터가 걸리면 항상 | 순수 개인 학습 목표 |
| L9 제품·빌드 (선택) | 앱·사이트·도구 자체를 만든다 | "앱 출시" 같은 목표, 또는 전환에 자체 페이지가 필요할 때 | 남의 플랫폼만 쓰는 목표 |

근거: 퍼널을 단계로 나눠 새는 곳을 찾는 AARRR, 채널과 제품이 서로 맞아야 한다는 Balfour의 4 fits(제품-채널 적합), 채널을 여러 개 싸게 시험한 뒤 하나에 집중하라는 Traction의 Bullseye(Weinberg & Mares, 2015).

### 렌즈별 상세

**L1 오퍼·포지셔닝**
- 대표 할 일: 대상 한 문장 정하기("자취 1년 차 직장인") · 경쟁 계정·페이지 5개 조사 · 차별점 한 줄 · 이름·프로필 문구
- 완료 조건 예: "프로필 첫 줄을 보고 누구를 위한 계정인지 3초 안에 알 수 있다"를 지인 1명에게 확인
- AI: 경쟁 조사, 포지셔닝 후보 5개, 문구 초안 / 사람: 하나 고르기, 지인 확인
- 규칙: 대상이 "모두"이면 미완료다. 좁을수록 하루 10분 콘텐츠가 쉬워진다.

**L2 고객유치(채널)**
- 대표 할 일: 후보 채널 3개 고르기(§8) · 채널별 규칙 읽기 · 2주 시험 계획
- 완료 조건 예: 채널 1개에서 2주 동안 측정 가능한 클릭이 나온다
- AI: 채널 규칙 조사, 시험 계획, 결과 비교 / 사람: 계정 가입·본인 인증·게시
- 규칙: 처음엔 **채널 1~2개만**. 채널마다 계정 관리 비용이 든다.

**L3 홍보·콘텐츠**
- 대표 할 일: 콘텐츠 형식 2~3개 정하기 · 글 템플릿 · 주제 백로그 30개 · 매일 초안
- 완료 조건 예: 템플릿대로 쓴 초안을 사람이 2분 안에 고쳐 올릴 수 있다
- AI: 주제 발굴, 초안, 이미지 설명, 해시태그 후보 / 사람: 사실 확인, 말투 손보기, 게시
- 규칙: 초안에는 **확인한 사실만**. 써 보지 않은 상품을 "써 봤다"고 쓰지 않는다.

**L4 전환**
- 대표 할 일: 링크 모음 페이지 · 글 안의 CTA 위치 · 표기 문구 위치 · 클릭 추적(UTM·서브태그)
- 완료 조건 예: 채널별 클릭이 따로 집계된다
- AI: 페이지 코드, 문구 후보 / 사람: 배포 계정, 도메인 결제
- 규칙: 압박형 문구("오늘만", "곧 품절") 금지. 사실일 때만, 근거와 함께.

**L5 운영툴·자동화**
- 대표 할 일: 주간 숫자 입력 폼 · 초안 생성 프롬프트 고정 · 게시 체크리스트 · 백로그 시트
- 완료 조건 예: 주간 점검 입력이 2분 안에 끝난다
- AI: 스크립트·템플릿·대시보드 제작 / 사람: 외부 계정 연결 승인
- 규칙: 외부 계정에 **자동 게시하는 도구는 만들지 않는다**(§3-3).

**L6 리텐션·커뮤니티**
- 대표 할 일: 재방문 이유 만들기(주간 정리 글·시리즈) · 댓글 답글 · 구독/팔로우 유도 문구
- 완료 조건 예: 지난주 방문자 중 재방문 비율이 측정된다
- AI: 시리즈 기획, 답글 초안 / 사람: 실제 답글 게시
- 규칙: 리텐션이 안 보이는데 유치를 늘리지 않는다(밑 빠진 독). 획득 확대는 재방문·재구매가 평평하게 남는 걸 본 뒤.

**L7 측정·수익**
- 대표 할 일: 지표 트리 확정 · 숫자 출처 정하기 · 주간 입력 · 2주 차 가정 교체
- 완료 조건 예: 지표 트리의 모든 칸에 "측정값" 또는 "가정 + 측정 경로"가 있다
- AI: 계산, 차트, 해석 / 사람: 대시보드에서 숫자 복사(로그인 필요)

**L8 규정·리스크**
- 대표 할 일: 광고 표기 템플릿 · 플랫폼 금지 행위 목록 · 세금 메모 · 회사 겸업 규정 확인
- 완료 조건 예: 게시 체크리스트에 표기·금지 행위 항목이 들어갔다
- AI: 규정 조사·요약 / 사람: 회사 규정 확인, 세금 신고
- 규칙: 확인 못 한 규정은 "확인 필요 — 어디에 물을지"로 남긴다. 법률 판단은 하지 않는다.

**L9 제품·빌드 (선택)**
- 대표 할 일: 최소 기능 정의 · 빌드 · 배포 · 첫 사용자 5명
- AI: 코드 대부분 / 사람: 스토어·도메인·결제 계정, 심사 제출

## 2. 목표 숫자 역산 (지표 트리)

### 2-1. 방법

1. 출력 지표(월 수익·팔로워 수)를 곱셈 사슬로 나눈다. 칸마다 `값 · 출처/가정 · 측정 경로`를 적는다.
2. 각 칸을 ±50% 흔들어 출력이 얼마나 바뀌는지 본다(민감도). 가장 크게 움직이고 내가 손댈 수 있는 칸이 첫 레버다.
3. 사람이 손댈 수 없는 칸(수수료율·플랫폼 알고리즘)은 레버가 아니라 **제약**으로 표시한다.
4. 역산 결과 필요한 상단 숫자(노출·방문)가 하루 N분으로 불가능하면, 목표를 단계 목표로 쪼갠다(예: 1단계 월 1만 원).

근거: 출력 지표를 입력으로 나누고 민감도로 레버를 고른다(듀오링고 성장 모델, Lenny's Newsletter 2023-02-28). 북극성은 직접 못 움직이고 입력으로만 움직인다.

### 2-2. 표준 트리

| 목표 유형 | 사슬 |
|---|---|
| 제휴·추천 수익 | 월 수익 = 노출 × 클릭률 × 구매 전환율 × 객단가 × 수수료율 |
| 내 상품 판매 | 월 수익 = 방문 × 구매 전환율 × 객단가 − 비용 |
| 팔로워 | 순증 = 노출 × 프로필 방문률 × 팔로우율 − 이탈 |
| 앱 출시·사용 | 주간 활성 = 신규 설치 × 활성화율 + 기존 × 유지율 |
| 뉴스레터 | 구독자 순증 = 방문 × 구독 전환율 − 구독 해지 |

### 2-3. 가정을 측정으로 바꾸는 법

- 처음엔 모든 모르는 칸이 `[가정]`이다. 범위(낮음/중간/높음)로 둔다. 한 값만 쓰지 않는다.
- **첫 2주**는 실험이 아니라 측정 기간이다. 목표: 칸마다 실제 값 1개.
- 표본이 작으면(클릭 30건 미만 [가정: 경험칙]) 값을 확정하지 않고 "잠정"으로 둔다.
- 2주 차 주간 점검에서 가정 → 측정값으로 바꾸고 역산을 다시 한다. 필요 상단 숫자가 2배 이상 바뀌면 웨이브 계획을 고친다.
- 외부 벤치마크(업계 클릭률 등)를 쓸 때는 분모·기간·출처 수준(원문/2차)을 같이 적는다. 다른 계정의 숫자를 내 목표로 쓰지 않는다.

## 3. 하루 N분 예산

### 3-1. 규칙

- 사람 시간이 유일한 희소 자원이다. 루프와 할 일의 **사람 몫(분)** 합계가 예산을 넘으면 설계가 틀린 것이다.
- 예산 배분 기본값 `[가정]`: 반복 루프 70% · 이번 주 할 일 20% · 여유 10%. 하루 10분이면 7분 / 2분 / 1분.
- 0주차(셋업)는 예외다. 계정 가입·인증·첫 설정에 한 번에 30~90분이 든다. 이걸 숨기지 말고 "0주차 1회성 시간"으로 따로 적는다.
- 주간 루프의 사람 몫은 7로 나눠 하루 평균에 넣는다.
- 사람 몫이 같은 일이면 **배치**한다: 매일 3분 × 5일 대신 일요일 15분 한 번이 집중 전환 비용이 적다.

### 3-2. 경계

| 사람만 (AI가 하지 않는다) | AI가 한다 |
|---|---|
| 계정 가입·본인 인증·약관 동의 | 조사·요약·비교 |
| 외부 채널 게시·댓글·DM | 글·이미지 설명·스크립트 초안 |
| 결제·계좌·세금 신고 | 지표 계산·주간 리포트 |
| 상품을 실제로 써 보고 판단 | 템플릿·체크리스트·도구 코드 |
| 로그인이 필요한 대시보드에서 숫자 복사 | 백로그 정리·우선순위 제안 |
| 최종 선택(무엇을 올릴지) | 위험·규정 점검 |

### 3-3. 자동 게시는 기본으로 하지 않는다

- AI는 초안을 만들고, 사람이 복사해서 올린다. 이유: (1) 플랫폼 약관이 자동화·봇 게시를 막는 경우가 많다 `[추정 — 플랫폼별 확인 필요]` (2) 광고 표기·사실 확인 책임은 게시한 사람에게 있다 (3) 계정 정지 위험은 사용자가 진다.
- 예외는 **사용자 소유 사이트**(내 블로그 서버·내 링크 페이지)뿐이고, 그것도 사용자가 켜겠다고 명시했을 때만.
- 사람 몫을 줄이는 방법은 자동 게시가 아니라 "복사 한 번에 끝나는 초안"이다: 표기 문구·링크 자리·해시태그까지 완성된 상태로 준다.

## 4. 자동 루프 설계

### 4-1. 루프 카드 형식

```
루프: {이름} · 주기: 매일/평일/매주/매월 · 시각
입력: {AI가 읽는 것}
산출물: {AI가 남기는 것 — 어디에}
사람 몫: {무엇을} {N분}
켜는 조건 / 끄는 조건:
겨누는 지표: {지표 트리의 칸}
```

### 4-2. 루프 예시

| 루프 | 주기 | 입력 | 산출물 | 사람 몫 |
|---|---|---|---|---|
| 콘텐츠 초안 | 매일 07시 | 주제 백로그, 어제 성과 | 게시용 초안 1~3개(표기 문구 포함) | 고르고 고쳐 올리기 3~5분 |
| 소재 발굴 | 평일 | 플랫폼 베스트·특가 공개 페이지 | 후보 5개 + 고른 이유 | 1개 고르기 1분 |
| 답글 초안 | 매일 저녁 | 사람이 붙여 넣은 새 댓글 | 답글 초안 | 확인·게시 2분 |
| 주간 점검 | 매주 일요일 | 사람이 입력한 주간 숫자 | 지표 트리 갱신, 실험 판정, 다음 주 할 일 3개 | 숫자 입력 3분 + 읽기 5분 |
| 백로그 정리 | 매주 | 쌓인 주제·아이디어 | 상위 10개 정렬 | 0분 |
| 규정 점검 | 매월 1일 | 플랫폼 공지·약관 페이지 | 바뀐 점 요약, 영향 | 읽기 2분 |
| 월간 회고 | 매월 말 | 4주 점검 기록 | 루프 켜기/끄기 제안, 목표 재역산 | 결정 5분 |

### 4-3. 규칙

- **처음엔 3~5개.** 0주차엔 측정 루프(주간 점검) 1개 + 핵심 생산 루프 1~2개면 충분하다.
- 모든 루프는 지표 트리의 한 칸을 겨눈다. 겨누는 칸을 못 적으면 켜지 않는다.
- **산출물은 하나로 모은다**: 매일 아침 "오늘 할 일" 한 장에 모든 루프의 사람 몫을 합친다. 루프마다 알림을 따로 보내지 않는다.
- 사람 몫이 0분인 루프도 수를 센다. 읽히지 않는 산출물은 소음이다.

### 4-4. 피로 방지

- 사람이 산출물을 **3일 연속 안 열면** 다음 루프부터 양을 절반으로 줄이고, 7일이면 생산 루프를 멈추고 "다시 켤까요?" 한 줄만 남긴다. 죄책감 문구·스트릭 압박 금지.
- 하루 초안이 3개를 넘지 않는다. 고르는 시간도 사람 몫이다.
- 새 루프를 켜려면 기존 루프 하나를 끄거나, 사람 몫 합계가 예산 안임을 보인다.

### 4-5. 2주마다 켜고 끄는 기준

| 판정 | 기준 |
|---|---|
| 유지 | 겨누는 지표가 움직였거나, 측정 중(아직 표본 부족) |
| 수정 | 산출물이 쓰이지만 지표가 안 움직임 → 입력·형식 하나만 바꿔 2주 더 |
| 끄기 | 4주간 지표 변화 없음, 또는 사람이 산출물의 절반 이상을 안 씀 |
| 켜기 | 주간 점검에서 새 병목이 확인되고 예산에 자리가 있음 |

끈 루프는 지우지 않고 "꺼짐 — 이유 한 줄"로 남긴다(진 실험도 학습이다 — Balfour growth meeting).

## 5. 단계 (웨이브)

| 웨이브 | 기간 | 목표 | 진입 기준 | 다음으로 넘어가는 기준 | 중단·전환 기준 |
|---|---|---|---|---|---|
| W0 셋업 | 0주차 | 계정·표기·측정이 준비된 상태 | 목표 문장 확정 | 첫 게시 1건 + 클릭이 집계됨 | 플랫폼 가입 불가·약관상 불가 → 목표 재설계 |
| W1 첫 신호 | 1~2주 | 지표 트리의 가정을 측정값으로 | W0 완료 | 클릭 1건 이상 + 전환 경로 확인 | **2주간 클릭 0** → 채널 또는 형식 바꾸기(같은 걸 더 하지 않는다) |
| W2 반복 | 3~6주 | 효과 있는 형식·채널 하나에 집중, 재방문 확인 | 측정값이 있는 채널 1개 | 4주 연속 같은 방향 + 재방문 신호 | 4주간 전환 0 → 오퍼(L1)부터 다시 |
| W3 확장 | 7주~ | 두 번째 채널 시험, 반복 작업 도구화 | W2에서 주간 수익/성과가 평평하게 유지 | — | 사람 몫이 예산 초과 → 루프 줄이기 |

규칙
- 다음 웨이브로 가는 기준은 **숫자**로 적는다. "반응이 좋으면"은 기준이 아니다.
- 잘 되는 채널도 클릭률은 결국 떨어진다(Andrew Chen, Law of Shitty Clickthroughs, 2012). W2부터 다음 후보 채널 하나를 작게 시험해 둔다.
- 1~2주차엔 최적화하지 않는다. 처음엔 확장 안 되는 수작업으로 반응을 직접 본다(Paul Graham, "Do Things That Don't Scale", 2013).

## 6. 주간 점검

### 6-1. 보는 것 (이 순서로, 5분)

1. 지표 트리 숫자: 지난주 vs 이번 주, 가정 → 측정 바뀐 칸
2. 가장 약한 칸 하나(병목)
3. 진행 중 실험 판정
4. 사람 몫 실제 사용 시간 vs 예산
5. 위험 신호(경고 메일, 게시물 삭제, 규정 변경)

### 6-2. 서브 프로젝트 추가·중단·변경

- **추가**: 병목이 지금 없는 렌즈에 있을 때만. 한 주에 하나만.
- **중단**: 4주 동안 겨누는 지표 변화가 없거나, 병목이 다른 곳으로 옮겨 갔을 때.
- **변경**: 같은 칸을 겨누되 방법만 바꿀 때(형식·채널·시간대).
- 우선순위는 **도달 × 효과**로 비교한다. 작은 세그먼트의 큰 상승보다 큰 모수의 작은 상승이 클 때가 많다(Chen 2018).

### 6-3. 실험 카드 (짧게)

```
가설: {무엇을} 바꾸면 {지표 칸}이 {방향} — 왜냐하면 {근거}
도달: 주 {N}명/회 · 기대 기여: 도달 × 효과 = 월 {X}
기간: 2주 · 성공: {숫자} · 중단: {숫자}
결과: {숫자}
배운 것 한 줄:
세 질문: 유효한가? / 무엇을 더 말하나? / 어디에 또 쓰나?
```

## 7. 정직·안전 원칙

이 절은 다른 모든 절보다 우선한다. 걸리면 설계를 바꾼다.

### 7-1. 정직
- **수익 보장 금지.** "월 10만 원 가능"이 아니라 "필요한 숫자는 이것, 현재 측정값은 이것". 역산이 비현실적이면 그대로 말한다.
- 쓰지 않은 상품의 사용 후기를 쓰지 않는다. AI 초안의 "써 보니" 같은 문장은 사람이 실제로 쓴 경우에만 남긴다.
- AI가 만든 이미지·가상 인물은 AI임을 표시한다(토스 쉐어링크 대가성 문구 가이드 [사실: sharelink-docs.toss.im/disclosure, 2026-11-01]).

### 7-2. 광고·제휴 표기 (한국)
공정위 「추천·보증 등에 관한 표시·광고 심사지침」 기준:
- 구매 링크를 넣고 **판매 실적에 따라 수수료를 받는 경우도 표시 대상**이다(2024-12-01 시행 개정) [사실: 신&김 뉴스레터 2613 https://www.shinkim.com/kor/media/newsletter/2613, 조회 2026-11-01].
- 블로그·카페 등 **문자 중심 매체는 제목 또는 첫 부분**에 표시. 끝 부분 표시는 더 이상 안 된다 [사실: 신&김 뉴스레터 2613, 조회 2026-11-01].
- "소정의 수수료를 지급받을 수 있음"처럼 **조건부·불확정 표현은 불명확한 표시**로 본다 → "받습니다"로 단정해서 쓴다 [사실: 신&김 뉴스레터 2613, 조회 2026-11-01].
- 2025-12-02 안내서 개정: 미래·조건부 대가도 표시 대상, 표시 일반원칙은 접근성·인식가능성·명확성·언어 동일성 [사실: 아주경제 https://www.ajunews.com/view/20251202085042877, 2025-12-02, 조회 2026-11-01].
- 영상은 제목 또는 시작 부분에 넣고 반복 표시, 사진형은 사진 안이나 본문 첫 부분(2020-09-01 시행 개정 보도) [사실: 이투데이 https://www.etoday.co.kr/news/view/1909454, 조회 2026-11-01].
- `#ad`, `제휴 링크`처럼 수수료 사실이 안 드러나는 짧은 표시는 쓰지 않는다[사실: sharelink-docs.toss.im/disclosure, 조회 2026-11-01]. 정확한 조문은 공정위 예규 원문 확인 필요.

### 7-3. 금지 (설계에 넣지 않는다)
- 허위·조작 후기, 자전 거래(가족·지인 결제), 다계정, 자동 댓글·자동 좋아요·자동 팔로우, 남의 글에 링크 댓글
- 수신 동의 없는 메시지·메일 광고(정보통신망법상 원칙적으로 사전 동의 필요 — 토스 이용 주의사항이 같은 취지로 금지 [사실: sharelink-docs.toss.im/precautions, 조회 2026-11-01])
- 클릭에 보상을 주는 방식(보상형 클릭)
- 타인 이미지·후기 무단 사용, 플랫폼 로고·사칭
- 다크 패턴: 거짓 긴급성(가짜 "곧 마감"), 숨은 조건, 사전 선택, 해지·탈퇴 방해, 반복 간섭. 개정 전자상거래법 다크패턴 6유형(2025-02-14 시행) [사실: 뉴시스 2025-02-13, ROLE.md 재인용, 조회 2026-10-17]에 걸릴 소지가 있으면 `법무 확인 필요`
- 결과를 부풀리는 "수익 인증" 연출

### 7-4. 플랫폼 약관
- 채널마다 홍보 규칙이 다르다. W0에서 **사용할 채널의 규칙을 실제로 읽고** 요약을 L8 카드에 남긴다. 못 읽었으면 그 채널에 게시하지 않는다.

### 7-5. 세금·직장 (짧게)
- 부수입도 소득이다. 원천징수(예: 3.3%)가 됐어도 다른 소득과 합쳐 다음 해 5월 종합소득세 신고 대상일 수 있다 `[추정 — 홈택스·세무 상담으로 확인]`.
- 회사 취업규칙의 겸업 조항을 사람이 확인한다(AI는 회사 규정을 모른다).

### 9-2. 목표 재작성과 지표 트리

목표: "2027-01 말까지 토스 쉐어링크 확정 수익 월 10만 원, 사람 시간 하루 평균 10분 이하" `[가정: 기한은 사용자 미지정 → 3개월]`

```
월 10만 원 = 노출 × 클릭률 × 구매 전환율 × 객단가 × 수수료율
수수료율 5% (사실, 11-05~)            → 필요한 링크 경유 결제액 = 200만 원/월
객단가 2만 원 [가정, 범위 1~4만]        → 구매 100건/월 (하루 3.3건)
구매 전환율 3% [가정, 범위 1~5%]        → 클릭 약 3,300회/월 (하루 110회)
클릭률 2% [가정, 범위 0.5~3%]           → 노출 약 16.7만/월 (하루 5,500)
```

판정: 하루 10분으로 W1에 도달하기 어렵다. 처음부터 말한다.
- 민감도: 수수료율은 제약(손댈 수 없음). 객단가가 2배면 필요 클릭이 절반 → **객단가 높은 상품군 선택**이 사람 시간이 안 드는 레버. 다음은 클릭률(글 형식).
- 단계 목표 제안: W1 첫 확정 수익 1건 → W2 월 1만 원 → W3 월 3만 원 → 10만 원은 W3 측정값으로 재역산 후 판단.
- 결정할 것: (1) 기한 3개월이 맞나 (2) 1단계 목표를 월 1만 원으로 낮추는 데 동의하나 (3) 회사 겸업 규정 확인했나.

### 9-3. 서브 프로젝트

| # | 렌즈 | 서브 프로젝트 | 대표 할 일(완료 조건) | AI / 사람 |
|---|---|---|---|---|
| 1 | L1 | 니치 정하기: "자취 직장인 생활용품 특가" 같은 좁은 대상 | 후보 니치 3개 비교 → 1개 선택(프로필 첫 줄 완성) | AI 조사·후보 / 사람 선택 |
| 2 | L2 | 채널 1개 시험: 스레드 우선, 네이버 블로그 예비 | 스레드 규칙 확인, 계정 프로필, 2주 시험 계획 | AI 계획 / 사람 가입·게시 |
| 3 | L3 | 매일 1~2개 짧은 추천 글 | 템플릿(문제 → 상품 → 가격·근거 → 표기 → 링크) 고정, 주제 백로그 30개 | AI 초안 / 사람 사실 확인·게시 |
| 4 | L4 | 내 링크 모음 페이지(선택, W2) | 정적 페이지, 링크마다 옆에 표기, 채널별 클릭 집계 | AI 코드 / 사람 배포 |
| 5 | L5 | 운영툴: 주간 숫자 입력 폼 + 오늘 할 일 한 장 | 입력 2분 이내 | AI 제작 |
| 6 | L7 | 측정: 실적 대시보드(30분 단위 예상 수익) → 주간 입력 | 지표 트리 모든 칸에 측정 경로 | 사람 복사 / AI 계산 |
| 7 | L8 | 규정: 표기 템플릿·금지 목록·세금 메모 | 게시 체크리스트에 반영 | AI 정리 / 사람 회사 규정 확인 |
| 8 | L6 | 재방문: 주 1회 "이번 주 특가 정리" 시리즈 | W2 진입 후, 재방문 측정되면 유지 | AI 초안 / 사람 게시 |

### 9-4. 자동 루프 (사람 몫 합계 하루 10분 이내)

| 루프 | 주기 | 입력 | 산출물 | 사람 몫 |
|---|---|---|---|---|
| R1 후보+초안 | 평일 07시 | 토스쇼핑 공개 페이지·지난 성과·니치·템플릿 | 후보 3개와 후보마다 표기 문구가 첫 줄에 들어간 초안 1개(고를 것 합쳐 3개) | 하나 골라 앱에서 링크 발급·고쳐 게시 6분 |
| R3 답글 초안 | 평일 21시 | 사람이 붙여 넣은 댓글 | 답글 초안 | 확인·게시 1분 |
| R4 주간 점검 (시스템이 붙이는 루프 — 설계에 넣지 않는다) | 일요일 | 대시보드 숫자(사람 입력) | 지표 트리 갱신, 실험 판정, 다음 주 니치·형식 제안 | 입력 3분 + 읽기 5분 (하루 평균 약 1.1분) |
| R5 규정 점검 | 매월 1일 | 쉐어링크 공지·주의사항 페이지 | 수수료·정책 변경 요약 | 읽기 2분 (하루 평균 약 0.1분) |

합계: 평일 7분(R1 6분 + R3 1분) + 주간·월간 환산 약 1.2분 = **하루 평균 약 9분** `[가정: 각 작업 시간은 추정치, 2주 차에 실제 시간으로 교체]`.
자동 게시 없음 — R2는 복사 한 번이면 끝나는 완성 초안까지만.

### 9-5. 0~6주 단계

| 주 | 할 일 | 넘어가는 기준 | 중단·전환 기준 |
|---|---|---|---|
| 0주(11-01~11-04) | 점검 기간이라 링크 생성 불가 → 이 기간에 가입·채널 등록·니치 결정·템플릿·백로그 30개 준비 (1회성 60분 [가정]) | 11-05 이후 첫 게시 1건 | 가입 불가·겸업 금지 → 목표 재설계 |
| 1~2주 | R1·R2·R4만 켬. 평일 1건 게시, 측정 | 클릭 1건 이상 | **2주간 클릭 0 → 채널(스레드→블로그) 또는 형식 변경** |
| 3~4주 | 클릭률·전환율 가정 교체, 객단가 높은 상품군 실험 1개 | 첫 결제 발생 | 클릭은 있는데 4주간 결제 0 → 니치(오퍼) 재선정 |
| 5~6주 | R3 켬, 주간 정리 시리즈(서브 8), 다음 후보 채널 작게 시험 | 주간 예상 수익이 2주 연속 유지 | 사람 몫이 하루 12분 초과가 2주 → 루프 하나 끄기 |
| 7주~ | 10만 원 재역산 → 계속/목표 조정 결정 | — | — |

첫 정산 시점 주의: 11월 구매확정분은 12-25에 지급. 수익 확인은 대시보드 예상 수익으로 먼저 본다.

### 9-6. 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 수수료율 인하·프로모션 종료가 잦음(10% → 8% → 5%, 3개월 사이) | 역산 필요 숫자 2배 | R5 월간 점검, 수수료율을 제약 칸으로 두고 바뀔 때마다 재역산 |
| 표기 누락·위치 오류 | 지급 보류·계약 해지 | 템플릿 첫 줄 고정, 게시 체크리스트 |
| 광고성 계정으로 인식돼 노출 감소 [추정] | 클릭률 하락 | 링크 없는 정보 글 비율 유지, 주간 점검에서 노출 추이 확인 |

| 미니앱·API 경로 막힘 | 자동화 도구 설계 불가 | Open API 전제로 설계하지 않음, 공개 페이지 + 사람 링크 발급 |
| 목표 비현실 | 동기 저하 | 단계 목표, 수익 보장 문구 금지 |
| 세금·겸업 | 신고 누락·회사 문제 | L8 카드: 3.3% 원천징수 확인, 5월 신고 여부 상담, 취업규칙 확인 |

## 10. 설계 전 마지막 점검표

- [ ] 목표 문장에 무엇·얼마나·언제·하루 몇 분이 있다
- [ ] 지표 트리 모든 칸에 값 또는 `[가정] + 측정 경로`
- [ ] 비현실적이면 그 사실과 단계 목표를 먼저 말했다
- [ ] 서브 프로젝트 5~8개, 각자 겨누는 지표 칸이 있다
- [ ] 루프 3~5개, 사람 몫 분 합계가 예산 안
- [ ] 외부 계정 자동 게시 없음
- [ ] 웨이브마다 숫자로 된 넘어가기·중단 기준
- [ ] 광고 표기(제목/첫 부분, 단정형 문구)와 플랫폼 금지 행위가 게시 체크리스트에 있다
- [ ] 허위 후기·다계정·자동 댓글·무동의 메시지·다크 패턴 없음
- [ ] 확인 못 한 규정은 `확인 필요 — 어디에 물을지`
- [ ] 결정할 것(사용자에게 닫힌 질문) 최대 3개
