# 지식 · 교과서 탭 설계

> 교과서 6권(약 560개 노트)을 앱에서 차례대로 읽고, 정답을 가린 채 문제은행을 풀고, 읽은 노트를 내 말로 다시 써서 영구노트로 옮긴다. 교과서 파일은 앱이 고치지 않는다.

- 브리프: 사용자는 본인 1명. 주로 맥 데스크톱에서 쓰고, 폰(390px)에서는 가끔 읽는다. 성공 기준은 세 가지다. ① 다음 노트로 바로 넘어간다 ② 고르기 전에는 정답이 안 보인다 ③ 왜 고치기 버튼이 없는지 화면만 보고 안다. (P1)
- 실물 확인(2026-10-26): 6권 모두 노트가 전부 MOC에 링크돼 있다(목차에 없는 노트 0개). 문제은행은 파일 하나인 권(PKM·패션)과 폴더인 권(당구·FE·홀덤)이 있고, AI 교과서에는 없다. 대신 AI 교과서 MOC 안에 `[!question]-` 문항이 있다. 콜아웃은 `[!success]-` 513개, `[!check]-` 165개, `[!question]-` 83개로 **모두 접힘(-)** 이다. PKM 문제은행은 **맨 아래 `## 정답표`에 정답이 다 나온다**. 가장 긴 파일은 112KB(패션 문제은행)이고, MOC에는 7열 표가 있다.

## 1. 구조 — 요청한 3단(목록 → 책 → 노트)을 유지한다

더 줄이는 안을 두 가지 검토했지만 둘 다 버렸다.
- **참조노트 안에 섞기:** 참조노트는 읽기 상태를 바꾸고 고치는 노트다. 읽기전용 노트 560개가 섞이면 규칙이 갈리고 목록도 묻힌다. (P8·P12)
- **책 화면 없이 목록에서 바로 MOC로 가기:** 책 화면이 곧 MOC 렌더라서 실제로는 같은 안이다. 별도로 만드는 화면은 책 목록(6줄)과 노트 화면 둘뿐이다. (P2)

| 경로 | 화면 | 주요 행동 |
|---|---|---|
| `#/knowledge/tb` | 책 목록 | 책 열기 |
| `#/knowledge/tb/{bookId}` | 책 = MOC 본문(첫 `# ` 줄은 h1과 겹치니 뺀다) | 이어 읽기 / 처음부터 읽기 |
| `#/knowledge/tb/{bookId}/{noteId}` | 노트 | 다음 노트(맨 아래), 영구노트로 다듬기 |
| `#/refine/tb/{bookId}/{noteId}` | 기존 다듬기 화면을 재사용 | 영구노트로 저장하기 |

- **순서:** 책 안의 노트가 MOC에 처음 나오는 순서를 따른다. MOC에 없는 노트는 폴더 순서대로 맨 뒤에 붙인다. 이 순서가 이전/다음 링크와 `n/N` 표시의 기준이다.
- **읽기전용은 화면이 아니라 시스템이 지킨다:** 쓰기 층에서 교과서 경로에 저장·삭제·이름 바꾸기를 막는다. `EDIT_KIND`에 tb를 등록하지 않는다. 그래서 고치기 화면으로 가는 길이 아예 없다. (P12)
- **[[링크]] 찾는 순서:** 교과서 화면에서는 같은 책 노트 → 영구노트 → 참조노트 → 다른 책 순서로 찾는다. 다듬은 영구노트를 교과서 제목 그대로 저장했다면, 교과서 안의 링크가 그 영구노트로 새면 안 되기 때문이다. 내 노트(영구·참조·맥락) 화면에서는 기존 순서를 따르고 교과서를 맨 끝에 둔다. 내 영구노트에서 교과서 노트를 링크하면 교과서 노트가 열린다. (P4)

## 2. 화면

**책 목록** — seg에 5번째 탭으로 `교과서 6` / `읽기만 하는 책`을 붙인다. 기존 탭 4개의 위치는 그대로 둔다(P8). 탭이 5개가 되면 390px에 다 안 들어가므로 `seg-compact seg-scroll`을 쓴다(시간 탭과 같은 방식). 교과서 탭에 있을 때는 그 탭을 `scrollIntoView({inline:'nearest'})`로 화면 안에 보이게 한다.
```
┌──────────────────────────────────┐
│ 지식                               │
│ 참조 임시 영구 맥락 [교과서 6]       │
│ ─────────────────────────────── │
│ 개인지식관리 교과서              › │
│ PKM 처음부터 끝까지 · 노트 34       │
│ · 다듬은 노트 2 · 문제은행          │
└──────────────────────────────────┘
```
- 각 줄은 `<a class="row">`다. 제목에는 폴더 이름의 ` — ` 앞부분을 쓰고, meta에는 뒷부분, `노트 N`(MOC 제외), `다듬은 노트 N`(0이면 뺀다), `문제은행`(있을 때만)을 넣는다. 책 순서는 폴더 이름순이다.

**책** — MOC 본문이 곧 목차다(P2).
```
┌──────────────────────────────────┐
│ ‹ 교과서                           │
│ 교과서 · 노트 34                   │
│ 개인지식관리 교과서                 │
│ [이어 읽기]  [Obsidian에서 열기]    │
│ 7/34 · 아렌스의 노트 세 종류는…      │
│ 교과서는 원본 그대로 읽기만 해요…    │
│ ── MOC 본문(링크 = 목차) ──        │
└──────────────────────────────────┘
```
- 주요 버튼은 하나다(btn-primary). 마지막으로 연 노트가 있으면 `이어 읽기`, 없으면 `처음부터 읽기`(순서상 첫 노트로 간다). 마지막으로 연 노트는 기기 localStorage에만 둔다. 교과서 파일은 건드리지 않는다. 노트가 100개 넘는 권에서 읽던 자리를 MOC에서 다시 찾는 비용을 없애려는 것이다(P2). 이 버튼만 추가 기능이다.
- MOC에 없는 노트가 있으면 MOC 아래에 `<details class="more">`로 `목차에 없는 노트 N개`를 둔다. 0개면 아예 그리지 않는다.

**노트**
```
┌──────────────────────────────────┐
│ ‹ 개인지식관리 교과서               │
│ 교과서 · 03 제텔카스텐              │
│ 아렌스의 노트 세 종류는 보관 장소가   │
│ 아니라 처리 단계다                  │
│ [영구노트로 다듬기] [Obsidian에서 열기]│
│ 교과서는 원본 그대로 읽기만 해요…    │
│ ── 본문 ──                        │
│ 내가 다듬은 영구노트 1     (있을 때만)│
│ ── nav 교과서 순서 ──              │
│ ‹ 이전 노트 · 5/34                 │
│   루만의 제텔카스텐은 저장소가…       │
│   다음 노트 · 7/34               › │
│   폴게첼 번호는 위치로 맥락을…        │
└──────────────────────────────────┘
```
- eyebrow에는 `교과서 · {장 폴더 이름}`을 쓴다. 책 바로 아래에 있는 파일(문제은행·용어집)은 `교과서`만 쓴다. 본문 첫 줄이 `# {제목}`이면 뺀다.
- `영구노트로 다듬기`는 btn-tonal이다. 다른 화면의 다듬기 버튼과 같은 무게로 맞췄다(P8). 읽는 화면이라 btn-primary는 두지 않는다. 대신 화면 끝의 `다음 노트`가 자연스러운 다음 행동이다(P3). 문제은행·용어집·MOC에서는 다듬기 버튼을 숨긴다(개념 노트가 아니다).
- `내가 다듬은 영구노트 N`에는 `sources`에 이 노트가 든 영구노트·맥락노트를 row로 보인다. 0개면 섹션을 그리지 않는다(P2).
- 이전/다음은 `<nav aria-label="교과서 순서">` 안의 `<a class="row" rel="prev|next">` 두 줄이다. meta가 `이전 노트 · 5/34`, title이 노트 제목이다. 제목이 한 문장이라 길어도 줄을 바꿔 다 보인다. 맨 앞 노트에는 이전 줄을, 맨 끝 노트에는 다음 줄을 그리지 않고, 끝 노트에는 대신 `‹ {책 이름} 목차로` 한 줄을 둔다.

**다듬기(tb)** — 기존 vRefine을 쓰되 네 곳만 다르다.
- 섹션 이름은 `원래 노트`다. `교과서 · {책} · {장}` 다음에 노트 제목을 보이고, 본문은 `<details class="more"><summary>본문 펼치기</summary>`로 **접어 둔다**. 교과서 MOC의 승격 기준이 "제목만 보고 노트 없이 설명할 수 있는가"라서, 먼저 떠올리게 하려는 것이다.
- 제목 칸은 **비워 둔다**. 힌트는 "제목이 돼요. 교과서 문장 대신 내 말로 써요."다. 교과서 문장을 미리 채우면 내 말로 다시 쓰는 단계가 빠진다. 이 화면의 목표가 바로 그 단계다(사다리 2 '목표를 끝낸다' > 4 '단순하다'. P5의 미리 채우기를 포기한다).
- 연결 후보에는 교과서 본문의 [[링크]] 중 영구노트로 찾아지는 것을 먼저 놓고, 그다음에 기존 추천을 놓는다. 체크는 미리 하지 않는다(P2·P5).
- 저장하면 `sources: ["[[교과서 노트 제목]]"]`이 들어가고 새 영구노트로 이동한다. 교과서 노트는 지우지 않는다. vPerm의 `출처`도 교과서 노트를 찾도록 고친다. 출처 row의 meta는 `교과서 · {책 이름}`이다.

## 3. 콜아웃·정답 렌더 규격 (§5-1 추가)

- **인식:** 인용 블록의 첫 줄이 `^>\s*\[!(\w+)\]([+-]?)\s*(.*)$`이면 콜아웃이다. 뒤따르는 `>` 줄에서 `> `를 떼고 나머지를 **`md()`로 다시 렌더**한다. 굵게·[[링크]]·목록·표가 그대로 산다.
- **`-` (실물에 있는 형태는 이것뿐):** `<details class="more callout">`로 만들고 **닫힌 채** 둔다. `<summary>`는 제목의 `inline()` 결과다. AI 교과서의 `[!question]-`은 질문이 곧 제목이라 질문이 보이고 답이 접힌다.
- **`+`:** 열린 details로 만든다. **접미사 없음:** 접지 않는 `<div class="callout">` 박스로 만들고 제목을 굵게 한 줄 쓴다.
- **제목이 비었을 때:** success·check는 `정답과 해설`, question은 `질문`, 나머지는 `더 보기`로 채운다.
- **스크린리더:** `정답과 해설`이 64번 똑같이 읽히지 않게, 바로 앞 제목이 `Q\S+`로 시작하면 summary 끝에 `<span class="sr-only"> (Q1-1)</span>`을 붙인다.
- **정답표:** `^정답(표| 모음)`으로 시작하는 제목부터 같은 단계 이하의 다음 제목 전(또는 파일 끝)까지를 `<details class="more"><summary>정답표 펼치기</summary>`로 감싼다. 끝까지 스크롤해도 답이 안 보이게 하려는 것이다.
- **모양:** 타입별 색·아이콘은 쓰지 않는다(정보를 색으로만 주지 않고, 장식 이모지도 쓰지 않는다). 기존 `details.more` 스타일에 바깥 박스만 더한다. 박스는 `--surface-2` 배경 + 왼쪽 3px 경계선이고, 경계선 대비는 3:1 이상이다. summary는 줄 높이 44px 이상, 포커스 링은 기존 것을 쓴다.
- **다시 그릴 때:** render()로 main을 다시 그려도 열어 둔 details가 닫히지 않게 한다. 콜아웃마다 위치 인덱스로 `data-key`를 주고, 열린 key를 S에 기억했다가 같은 노트를 다시 그릴 때 `open`을 복원한다. 다른 노트로 가면 비운다.
- **원문 기호:** 본문의 ⊡·☌·⚙·📖 같은 원문 기호는 읽기전용 원본이므로 그대로 둔다. 앱이 그리는 부분(버튼·라벨)에는 장식 이모지를 넣지 않는다.

**웃음 자리 없음.** 읽기·문제 화면은 지시·라벨·정답이 나오는 자리라 웃음을 넣으면 안 된다. 책 0권 빈 상태는 처음에 한 번 가져오면 다시 안 생기는 설정 상태라 웃음을 넣을 가치가 없다.

## 7. 결정과 근거
- 탭을 맨 끝에 붙였다 — 기존 탭 위치를 지키는 P8을 따르고, 남의 글끼리(참조노트 옆) 묶는 의미 정렬은 포기했다.
- 고치기 버튼 대신 이유 한 줄을 고정으로 둔다 — 고치기를 기대하는 자리에서 왜 없는지 알려 준다(P4·P6). 안내 팁을 따로 띄우는 안은 P2로 뺐다.
- 콜아웃은 하나의 회색 박스로만 그린다 — P10(색만으로 구분 금지)과 P8(`details.more` 재사용)을 따른다.
- 고르면 바로 채점하는 퀴즈는 만들지 않는다 — 접힌 정답으로도 인출 연습이 된다(P12). 필요한지는 §8에서 확인한다.

## 8. 검증
- 성공 지표: 출처가 교과서인 영구노트 수(주간).
- 가드레일: ① 6권 문제은행 전 파일에서 펼치기 전에 정답 문자(①~④ 정답 줄, 정답표)가 보이는 곳 0곳 ② 320px에서 가로 넘침 0.
- 과제 테스트: 도움 없이 "PKM 03장 둘째 노트 열기 → 다음 노트 → 문제은행 Q3-1 풀기 → 그 노트를 영구노트로 다듬기"를 3분 안에 끝낸다.

## 9. 확인이 필요한 것
1. 가져온 뒤 Obsidian `01_임시노트`의 원본 교과서는 **지울까요, 그대로 둘까요?** 둘 다 두면 `Obsidian에서 열기`가 여는 사본과 원본이 따로 놀아 헷갈린다.
2. 문제은행은 **접힌 정답을 직접 여는 것으로 충분할까요, 보기를 눌러 바로 채점하는 기능이 필요할까요?** 기본안은 접힌 정답만 두는 것이다.
