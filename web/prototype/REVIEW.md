# PKM 웹 목업 — 디자인 검수·개선 (2026-10-24)

> 한 줄 결론: 구조와 흐름은 이미 탄탄했다. 가장 큰 문제는 **겉모양이 토스답지 않은 것**(회색 테두리 버튼과 테두리 카드가 화면마다 겹쳐 시끄러움, 두 단계 보기 전환이 같은 모양이라 위계가 안 보임)과 **지나간 블록에 opacity를 줘서 글자 대비가 기준 아래로 떨어진 것**이었다. 둘 다 고쳤고, 저장 위치 창의 id 중복 버그도 바로잡았다.

- 대상: `web/prototype/index.html` (+ SPEC.md 변경 기록 한 줄)
- 기준: `ui-ux-design` 원칙 P1~P16 · checklist · ux-writing (토스 TDS·라이팅 + WCAG 2.2)
- 바꾸지 않은 것: 기능·흐름·데이터, `data-act`·`data-change`·`data-form` 값, 요소 id, 함수 이름, 데이터 구조, 목업 막대. 전후 비교 결과 `data-*`·id 목록 동일.
- 확인 방법: 헤드리스 크롬(CDP)으로 실물 스크린샷 — 모바일 390px(라이트·다크), 데스크톱 1280px(라이트·다크), 320px, 글자 200%, 바텀시트 8종, 토스트, 처음 시작·처음 사용 안내·충돌·불러오기 실패·새 프로필 온보딩. 27개 경로를 돌려 JS 오류 0건과 화면마다 h1이 있는 것을 확인.

### 고치지 않고 남긴 것 (트레이드오프)
- **저장 위치 창의 비활성 버튼** — 체크리스트는 "비활성 대신 누르면 이유"를 권하지만, 바꾸려면 제출 처리(JS 동작)를 고쳐야 해서 기능 동결 범위를 넘는다. 버튼 문구가 이유를 말하고, 바로 위 [GitHub로 로그인]이 다음 행동이라 막히지는 않는다. 실제 앱에서는 비활성 대신 누르면 로그인 안내로. (P4 vs 제약)
- **편집 화면 [취소]** — ux-writing은 "취소" 대신 "닫기"를 권하지만, 편집 화면에서는 "고친 내용을 버린다"가 정확한 결과라 그대로 둠.
- **다크 모드 선택지 테두리**(`--line` 1.2:1) — 고르는 칸의 경계는 라디오 자체(3:1 이상)가 알려 주고, 선택되면 2px 파랑 테두리가 생긴다.
- **웃음 자리** — 기존 판정(임시노트를 다 비운 순간 한 곳, 끌 수 있음) 그대로. 새로 넣을 자리 없음(오류·삭제·지시·라벨 금지).
