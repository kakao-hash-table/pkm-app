# PKM 웹 — 화면 구성 목업 설계

> 혼자 쓰는 노트 저장소(data/)를 **오늘 · 지식 · 시간 · 행동** 네 영역으로 열어, "지금 뭘 하지"와 "생각을 다듬기"를 브라우저에서 몇 번의 클릭으로 끝내게 한다. 긴 글쓰기는 Obsidian에 맡긴다.

- 목업: `web/prototype/index.html` (단일 파일, 외부 라이브러리 없음). 브라우저로 바로 연다.
- 맨 위 검은 **목업 막대**는 제품 UI가 아니다. 화면 상태(데이터 있음/처음 시작/불러오는 중/실패/동시 편집 충돌), 처음 사용 안내, 자동화 자리 표시, 웃음 문구, 테마를 바꿔 볼 수 있다.
- 샘플 데이터는 모두 가상이고, 시각은 2026-10-23(금) 13:10으로 고정했다.

## 0. 설계 원칙 (모든 변경이 먼저 지킬 것)

**도메인 타입은 코드에 넣지 않는다.** 이 PKM은 오픈소스로 누구나 쓴다고 가정한다. "성과평가·동료평가·학기 회고·고객 정산"처럼 특정 사람·직업에만 의미 있는 것은 타입이나 화면으로 만들지 않고, 아래 네 층 중 3층(템플릿·모아 보기)으로 푼다. 새 기능을 넣기 전에 "이게 1층(방법론)인가, 3층(쓰임새)인가"를 먼저 묻는다.

| 층 | 무엇 | 누가 정하나 | 예 |
|---|---|---|---|
| 1. 핵심 모델 | 이 PKM의 방법론 | 코드(고정) | inbox / reference·fleeting·permanent·context / daily·record / project·area·routine·appointment, project → area 연결, 블록 종류(inbox·knowledge·time·action) |
| 2. 설정 | 사람마다 다른 값 | `data/<프로필>/_설정.md` | 폴더 이름, 언어, 하루 시작·끝, 비워 둘 시간 |
| 3. 템플릿·모아 보기 | 도메인별 쓰임새 | 사용자(예시 템플릿을 함께 배포) | "성과평가" 템플릿 = 단기 + 모아 보기 블럭, 기록 종류(회의록·여행·요리…), 참조노트 형식(팟캐스트·강의…) |
| 4. 자동화 | 반복 작업 | 사용자·플러그인 | AI 자기평가 초안 |

**저장 값은 영어 키, 화면 이름은 언어 파일.** 노트에 저장되는 type·status·format·unit 값은 영어 키로 쓰고, 화면에는 언어 설정(`locale`)에 맞는 이름으로 보인다. 폴더 이름은 프로필 설정 `folders:`에서 키 → 폴더로 매핑한다(이름은 자유).

| 무엇 | 저장 키 (화면 이름 ko) |
|---|---|
| type | inbox(인박스) · reference(참조노트) · fleeting(임시노트) · permanent(영구노트) · context(맥락노트) · textbook(교과서 — 읽기전용, §0-1) · daily(데일리) · record(기록 — `kind`에 사용자가 만든 종류 이름: 회의록·여행·요리…) · project(단기) · area(장기) · routine(루틴) · appointment(약속) · settings(설정) |
| 단기 status | todo(대기) · doing(진행) · waiting(기다림) · done(완료) |
| 참조노트 format / status | book(책) · article(아티클) · video(영상) + 사용자가 추가한 형식(이름 그대로) / to_read(읽을 것) · reading(읽는 중) · processed(정리 완료) |
| 장기 unit | hours(시간) · books(권) · times(회) |

> 목업(index.html)은 화면 확인용이라 내부 값이 아직 한국어다. 실제 구현은 위 키로 저장한다.

### 0-1. 읽기전용 지식 — 교과서 (2026-10-26)
남이 쓴 글(참조노트)도 내 생각(영구노트)도 아닌, **완성된 채로 들여온 묶음 지식**(교과서·강의 노트·사내 핸드북처럼 목차가 있고 노트끼리 링크로 이어진 것)은 고치지 않고 읽고 꺼내 쓰기만 한다. **원본(예: Obsidian 볼트)이 정본**이고 pkm의 교과서는 복제본이다 — 원본을 고치면 서버가 알아서 다시 복제한다.

| 규칙 | 내용 |
|---|---|
| 위치 | `01_지식/교과서/<책 이름>/` (설정 `folders.textbook`으로 바꿀 수 있다). 책 안의 장 폴더 구조는 원본 그대로 둔다 |
| 판정 | 교과서 폴더 안의 `.md`는 프런트매터가 없어도 교과서다. 폴더 밖이라도 `type: textbook`이면 교과서다. `readonly: true`가 붙은 파일은 종류와 상관없이 앱이 쓰지 않는다 |
| 앱이 하는 것 | 읽어서 보여 주기, `[[링크]]` 잇기(내 노트 → 교과서 노트, 교과서 노트 → 내 노트), 영구노트로 다듬기(다듬은 영구노트의 `sources`에 교과서 노트가 들어간다) |
| 앱이 안 하는 것 | 고치기·이름 바꾸기·옮기기·지우기. `serialize`는 교과서를 파일 지도에 넣지 않고, 서버는 교과서 폴더나 `readonly: true` 파일을 건드리는 저장을 통째로 거절한다(403) |
| 프런트매터 | `type: textbook` · `id`(B…, 경로가 같으면 다시 가져와도 같다) · `title`(= 파일 이름 = 링크 대상) · `book` · `kind`(moc 목차 · note 개념 노트 · quiz 문제은행 · glossary 용어집) · `chapter`(장 폴더, 책 바로 아래 파일은 없음) · `order`(목차에 처음 나온 순서, 목차는 0) · `readonly: true` · `source`(원본 볼트 안 경로) · `imported`(처음 가져온 날) · `updated`(원본에서 본문이 바뀐 마지막 날 — 바뀐 적 없으면 없음. 날짜·`source`만 달라진 건 바뀜이 아니다) |
| 본문 | 맨 위 `# 제목` 줄은 뺀다(제목은 파일 이름). 개념 노트는 `# 내용` · `# 연결` · `# 활용` · `# 출처` 네 섹션(원본의 기호 붙은 섹션 이름은 기호 없이 바꾼다). 목차·문제은행·용어집은 원본 구조 그대로. 문제은행 정답은 Obsidian 접힘 콜아웃(`> [!success]- 정답과 해설`)으로 두고, 앱도 접힌 채로 보여 준다 |
| 가져오기 | 처음 한 번 `node scripts/import-textbook.mjs <책 폴더…> --to data/<프로필> --vault <원본 볼트>`. 원본은 건드리지 않는다. 책 폴더에 `.source.json`(원본 위치)을 남긴다 |
| 복제(자동) | 서버가 `.source.json`의 원본 폴더를 지켜보다가(파일 감시 + 5분마다 한 번 더) 바뀌면 그 책을 다시 복제한다. 본문이 같은 파일은 다시 쓰지 않는다. 원본에서 사라진 노트는 프로필 `.trash/`로 옮긴다. 원본 폴더가 없거나 비었으면 아무것도 지우지 않고 건너뛴다(원본이 없는 다른 기기도 마찬가지) |
| 보여 주기 | 앱이 다시 불러올 때 교과서 본문이 바뀌었으면 1개는 "원본에서 바뀐 교과서 노트를 불러왔어요"+[보기](그 노트), 여럿은 "… 노트 N개를 불러왔어요"+[목록 보기](책 화면). 책 화면 목차 위에 "2주 안에 바뀐 노트 N"(3개 보이고 나머지는 접힘), 노트 화면과 행에 "<날짜|오늘> 원본에서 바뀜". "Obsidian 원본 열기"는 복제본이 아니라 원본을 연다 |

### 0-2. 교과서 카드 — 휴대폰에서 넘겨 보는 짧은 카드 (2026-10-26)
교과서 노트는 평균 2,200자라 휴대폰 학습에 길다. 노트 하나를 영구노트 모양의 카드(주장 한 줄 제목 + 1~3문장) 여러 장으로 **다시 쓴** 것을 따로 둔다. 교과서 원문은 그대로다.

| 규칙 | 내용 |
|---|---|
| 위치 | `01_지식/교과서 카드/<책>/<장>/<노트 제목>.md` — 교과서 노트 하나에 카드 파일 하나(설정 `folders.cards`). 교과서 폴더 밖에 두는 건 교과서 복제(§0-1)가 원본에 없는 파일을 치우기 때문 |
| 프런트매터 | `type: cards` · `id`(C…) · `title`(노트 제목) · `book` · `chapter` · `from`(교과서 노트 id) · `from_hash`(만들 때 노트 본문의 해시 — 다르면 원본이 바뀐 것) · `readonly: true` · `made` |
| 본문 | `## 카드 제목(주장)` 한 줄, 바로 아래 `> [!question] 복습 질문?`, 빈 줄, 본문 1~3문장. 이 묶음이 카드 한 장 |
| 만드는 법 | `scripts/textbook-cards.prompt.md` 규칙대로 사람이나 AI가 쓴다. `node scripts/textbook-cards.mjs todo …`로 일감을 나누고, `write …`가 검사(개수 2~8, 제목 45자·질문 30자·본문 220자, 원문에 없는 숫자·링크 금지)를 통과한 것만 쓴다. `status`로 없는 카드·원본이 바뀐 카드를 센다 |
| 앱 | 책 화면 "카드로 공부하기/카드 이어 보기", 노트 화면 "카드 N장으로 보기". 한 장씩 보여 주고 이전·다음(옆으로 밀기, ←/→)으로 넘긴다 — 넘기기는 기록을 쌓지 않아 뒤로 가기는 책으로 간다. 처음 볼 때는 제목과 본문을 펼친 채로 보여 준다(처음 배우는 주제는 예시 먼저). 원본 노트가 바뀌었으면 "예전 내용일 수 있어요"를 알린다. 읽기전용 — 서버는 카드 폴더를 건드리는 저장을 거절한다 |
| 다음 | 질문(`q`)을 먼저 보여 주는 복습(다음 날 → 3일 → 7일 → 21일, 하루 5장, 벌점·스트릭 없음)은 아직 없다 |

### 아키텍처 결정 — 백엔드 없음, 로컬 우선 (2026-10-24)
- **데이터는 사용자 것에만 둔다.** 앱은 정적 웹(서버 코드 없음)이고, 데이터는 프로필마다 고른 곳에 마크다운 그대로 둔다.
  - `storage: device` — 이 기기의 브라우저에만(IndexedDB). PC 크롬·엣지에서는 폴더와 연결해 Obsidian 볼트로 함께 쓸 수 있다(File System Access API — 사파리·파이어폭스·모바일 브라우저는 안 됨). 브라우저 데이터를 지우면 사라지므로 내보내기(zip)·가져오기를 둔다.
  - `storage: github` — 사용자의 비공개 저장소. 브라우저가 GitHub API로 직접 읽고 쓴다(파일 sha로 충돌 감지, 몇 초 모아 커밋 하나, 오프라인이면 쌓았다 올림). 어느 기기·브라우저에서든 로그인만 하면 같은 데이터. PC Obsidian은 Obsidian Git으로 같은 저장소를 쓴다.
- **로그인:** 처음엔 저장소 하나 권한의 개인 토큰(서버 0), 이후 GitHub App + 토큰 교환용 Cloudflare Worker 하나(무료 범위, 데이터는 거치지 않음).
- **배포:** Cloudflare Pages(또는 Workers 정적 파일) 무료. 앱 저장소(공개)와 데이터 저장소(비공개)를 나눈다 — 한 저장소에 두면 공개 시 데이터도(기록까지) 공개된다. `_headers`로 CSP(외부 스크립트 금지, 연결은 api.github.com만).
- **서버가 필요해지는 조건:** 앱이 꺼져 있을 때 도는 일(자정 정리·아침 자동 실행·캘린더 변경 수신)과 다른 사람과 실시간 공유. 예약 실행은 GitHub Actions로 저장소 안에서 해결할 수 있다.
- **회사 데이터:** 기본은 device. GitHub로 옮길 때 회사 정책 확인 안내.
- **앱 주소가 막힌 곳(회사망 등):** 앱은 정적 파일이라 어디서 띄워도 같다. 데이터 연동은 api.github.com만 열려 있으면 된다. ① `scripts/serve.sh` — 이 컴퓨터에서만(127.0.0.1) 띄움, `http://localhost:5270`. ② 같은 앱을 GitHub Pages에도 배포해 두 번째 주소로. ③ 로그인은 Cloudflare Worker를 거치는 "GitHub로 로그인" 외에 **"토큰으로 연결"**(저장소 하나·Contents 읽기/쓰기·만료일 있는 개인 토큰, 서버 0)을 함께 둔다. 브라우저 저장소는 주소마다 따로라 "내 기기에만" 데이터는 주소를 바꾸면 안 보인다(GitHub 저장 프로필은 같음).

| 사용자 | 상황 | 끝낼 일 | 성공 기준 | 제약 |

| 본인 1명 (Obsidian도 같이 씀) | 맥 데스크톱 브라우저가 주, 가끔 폰 | ① 떠오른 생각을 바로 담기 ② 오늘 할 것 보고 체크하기 ③ 메모·읽은 것을 영구노트로 다듬기 ④ 지난 하루·회의 돌아보기 ⑤ 장기 누적 기록 남기기 | 목업을 눌러 보고 "이 구조로 구현해도 된다 / 여기는 바꾸자"를 판단할 수 있다 | 토스 UX 원칙(P1~P16), 접근성·다크패턴 금지 최우선, 한국어, 라이트/다크, 마크다운 파일이 원본 |

**가정** (틀리면 알려 주세요)
- A1. 웹은 **보기·분류·짧은 입력**용이고, 긴 본문 편집은 Obsidian에서 한다. 그래서 상세 화면마다 "Obsidian에서 편집"을 보조 버튼으로 둔다.
- A2. 데일리는 사람이 쓰는 문서가 아니라 **그날 한 일이 자동으로 모이는 기록 + 한 줄 회고**다.
- A3. 회의록은 약속에서 시작한다(일시·참석자를 약속에서 가져온다).
- A4. 임시노트는 받은편지함처럼 비우는 곳이다. 영구노트로 옮기면 임시노트는 지운다(되돌리기 가능).

## 2. 재사용할 것

- 기존 디자인 시스템·컴포넌트: **없음**(`web/`이 비어 있음). 이번에 최소 토큰을 정의했다(§7).
- 그대로 쓴 용어(템플릿·폴더 이름과 같게, P8): 참조노트 · 임시노트 · 영구노트 · 데일리 · 회의록 · 단기 · 장기 · 루틴 · 약속 · 대기/진행/기다림/완료 · 읽을것/읽는중/정리완료(화면에서는 "읽을 것/읽는 중/정리 완료"로 띄어 표시, 파일 값은 그대로).
- 템플릿 필드(`data/_템플릿/*.md`)를 화면 요소와 1:1로 맞췄다. 템플릿 섹션 제목("한 줄 요약", "핵심 내용", "인상 깊은 문장", "인상 깊은 장면·말", "내 생각 → 영구노트 후보", "할 일", "완료 조건", "메모", "왜 관리하나", "누적 기록", "회고", "루틴 내용")을 화면 섹션 제목으로 그대로 쓴다.

## 3. 정보 구조와 흐름

```
오늘 ── 시간표(약속+오늘 루틴, 시간순) · 할 일(진행·마감 임박, 기다림은 접어서 따로) · 정리할 것(임시노트 수·읽는 중)
지식 ── 참조노트(남의 글) ─┐
        임시노트(빠른 메모) ─┴→ 영구노트로 다듬기 → 영구노트(다듬은 내 생각)
시간 ── 데일리(자동 수집 + 한 줄 회고) · 회의록(약속에서 시작, 할 일 → 단기로 보내기)
행동 ── 단기(칸반) · 장기(누적 기록) · 루틴(켜기/끄기, 주기) · 약속
전역 ── [메모하기] → 임시노트 (어느 화면에서나)
```

| 흐름 | 단계 | 줄인 것 | 원칙 |
|---|---|---|---|
| 생각 담기 | 메모하기 → 적기 → 저장(⌘↵) | 분류·제목·태그를 묻지 않는다. 담는 순간엔 글만 | P2·P5 |
| 영구노트 만들기 | 임시노트/참조노트 후보 → 다듬기 화면(원래 메모 + 한 문장 + 연결) → 저장 | 제목을 원래 메모 첫 문장으로 미리 채움, 연결 후보를 보여 주고 고르게(회상 대신 인식) | P5 |
| 행동 만들기 | 제목 → 보드 고르기(판단 순서대로 정렬된 4개) → 보드별 필수 1~2칸 → 만들기 | 4단계 예/아니오 마법사 대신 **한 화면에 판단 규칙을 설명으로 붙인 선택지**. 현재 보드를 기본값으로 | P2·P5 |
| 회의록 | 약속 → 회의록 쓰기(일시·참석자 자동) → 할 일 → 단기로 보내기 | 회의록 안 할 일을 손으로 옮기지 않음 | P2·P12 |
| 장기 쌓기 | 루틴 체크 → 장기 누적 기록에 자동 한 줄 / 장기 화면에서 직접 추가 | 누적 표를 손으로 고치지 않음 | P2 |

### 5-1. 마크다운 본문 렌더 규격 (Obsidian에서 쓴 글이 들어오는 자리)
- 지원: 제목(#~###, 화면 위계에 맞춰 두 단계 내림), 목록·중첩 목록, 인용(>), 표, 코드 블록, `인라인 코드`, **굵게**, `[[위키링크]]`(있는 노트면 링크, 없으면 점선 밑줄 "아직 없는 노트예요"), `![[첨부]]`(첨부 카드로), `[글](url)`(새 창 표시), `- [ ]` 체크(☐/☑ 표시).
- 표·코드는 **그 칸 안에서만** 가로 스크롤(키보드 포커스 가능한 영역, 이름 "표 — 옆으로 밀어 더 보기"). 페이지는 320px에서도 가로로 넘치지 않음(목업 20개 화면 확인).
- 길이: "핵심 내용"처럼 긴 섹션은 **최상위 항목 8개까지 보이고 나머지는 "나머지 N개 더 보기"로 접는다**(`details`). 요약("한 줄 요약")은 항상 맨 위에 강조.
- 빈 값: "아직 적지 않았어요". 프런트매터 빈 필드는 메타 줄에서 아예 뺀다(빈 칸 나열 금지, P2).
- 미지원(구현 시 결정): 콜아웃(`> [!note]`), Dataview 블록, 각주, 수식 → 지금은 원문 그대로 보이므로 구현 전에 실제 노트에서 쓰는지 확인.

## 8. 결정과 근거

1. **영역 4개 + 전역 메모하기 1개** — 폴더 구조(01_지식·02_시간·03_행동)를 그대로 메뉴로 하고, 매일 여는 첫 화면 "오늘"만 더했다. P8(익숙함: Obsidian과 같은 지도) · P3. 검색은 뺐다(P12 — Obsidian 검색이 있음). 필요하면 2단계에서.
2. **오늘 = 약속과 루틴을 한 시간표로 합침** — 둘 다 "정해진 시각"이라 사용자는 구분할 필요가 없다. 출처는 작은 글자(약속/루틴)로만. P2 vs P8(보드 구분 유지) → 단순함을 택하되 출처 표시로 보완.
3. **행동 만들기는 마법사 대신 한 화면 선택지** — 판단 순서 4개를 순서대로 놓고 설명에 판단 기준을 적었다. 4단계 예/아니오는 매번 3~4번 눌러야 한다. P2·P5(회상보다 인식) vs P4(단계별 안내) → 단순함.
4. **루틴 cron은 사람 말로 보여 주고 고르게** — 파일에는 cron 그대로 저장(Obsidian 호환), 화면은 "평일 07:00", 편집은 주기 select + 시각. P2(시스템이 복잡성을 떠안음)·P5.
5. **칸반 이동은 드래그 대신 카드 안 `select`** — 키보드·스크린리더로 끝낼 수 있게. P10이 P15(손맛)를 이긴다. 드래그는 나중에 추가해도 select는 남긴다.
6. **모바일 칸반은 상태 탭 하나씩(기본 진행)** — 좁은 화면에 네 칸을 쌓지 않고 탭으로 하나만 본다. 상태 변경은 카드의 버튼(다음 단계 주 버튼 + 갈래 보조 버튼 + ⋯)으로 하고, PC는 같은 동작에 드래그를 지름길로 더한다. 드래그만 되는 기능은 두지 않는다(P10).
7. **참조노트 "내 생각" 후보는 임시노트를 거치지 않고 바로 영구노트로 다듬기** — 템플릿 섹션 이름이 이미 "→ 영구노트 후보"이고, 읽으면서 쓴 내 생각이라 한 번 더 옮길 이유가 없다. 임시노트는 읽기와 무관한 빠른 메모용. P2(단계 줄임). → 원래 말씀하신 "참조 → 임시 → 영구" 직선 흐름과 다르니 확인 바람.
8. **임시노트를 영구노트로 옮기면 임시노트는 지운다(되돌리기 토스트)** — 확인 팝업 대신 Undo. P9. 파일은 실제로는 휴지통/보관으로 옮기는 게 안전(구현 시 결정).
9. **데일리는 자동 수집 + 한 줄 회고만 입력** — 사람이 쓰는 칸을 최소로. P2·P12. 자동화(AI) 자리와 겹친다.
10. **장기 상세에 합계 3개만, 차트 없음** — 이번 달·지난달·전체. 증감은 "▲" 색 대신 두 숫자를 나란히. P12. 차트는 기록이 쌓인 뒤 실데이터로 판단(P16).
11. **시간 단위는 분으로 입력, 시간으로 저장** — 0.25시간 대신 "15분"을 쓰고 보여 준다. P5(이미 아는 단위로 답하기).
12. **"Obsidian에서 편집"은 모든 상세의 보조 버튼** — 웹은 긴 편집을 하지 않는다(A1). 다만 할 일 한 줄·회의록 새로 쓰기·한 줄 회고·누적 기록은 웹에서 바로. P12.
13. **비활성 버튼 없음** — 빈 입력으로 누르면 칸 아래에 이유. 체크리스트 §1 비활성.
14. **새 컴포넌트(이유)** — 디자인 시스템이 없어 카드·목록 행·세그먼트(링크)·배지·토스트·빈 상태·안내 줄을 최소로 만들었다. 각 하나씩만, 화면별 예외 컴포넌트 없음(P8).

### 자동화(AI) 자리 — 목업에서 "자동화 자리 표시"를 켜면 점선으로 보인다
| 자리 | 하는 일 | 지금 화면에서 대신하는 것 |
|---|---|---|
| 루틴 체크 → 장기 | 연결된 장기 누적 기록에 한 줄 추가(표에 "자동" 표시) | 목업에서 실제로 동작(아침 스트레칭) |
| 장기 누적 기록 | 운동·독서 앱 등에서 기록 가져오기 | 직접 추가 폼 |
| 데일리 "이날 한 일" | 그날 체크·완료·약속·노트·기록을 모음 | 목업에서 오늘 데이터로 계산 |
| 메모하기 | 메모에 맞는 영구노트·단기 후보 추천 | 없음 |
| 행동 만들기 | 제목으로 보드 미리 고르기(바꿀 수 있게) | 현재 보드가 기본값 |
| 참조노트 만들기 | 링크로 제목·저자·길이 채우기 | 직접 입력 |
| 다듬기 연결 후보 | 의미가 가까운 영구노트 추천 | 낱말 겹침으로 흉내 |
| 회의록 할 일 | 논의에서 할 일 뽑아 단기 후보로 | 직접 추가 |
| 약속 | 구글 캘린더 동기화 | "아직 연결 전" 표시 |

자동으로 들어간 것은 **항상 출처를 표시하고 되돌릴 수 있게** 한다(P9·P11). 자동이 사용자 기록을 덮어쓰지 않는다.

## 9. 검증 계획

- **성공 지표:** 임시노트가 생긴 뒤 영구노트로 옮기거나 지우기까지 걸린 시간(중앙값) — 7일 안이면 성공. 메모함이 실제로 비워지는지가 이 구조의 핵심 가설.
- **가드레일:** ① Obsidian에서 직접 고친 횟수 대비 웹에서의 충돌 발생 0건 ② 웹에서 만든 노트의 프런트매터가 템플릿과 어긋나는 일 0건(Dataview 쿼리가 안 깨짐).
- **방법:** 목업 단계에서는 본인이 과제 5개를 소리 내어 해 본다 — ① 떠오른 생각 하나 담기 ② 오늘 루틴 체크하고 장기에 쌓인 것 확인 ③ 임시노트 하나를 영구노트로 ④ 회의록에서 할 일을 단기로 ⑤ 새 할 일을 어느 보드에 넣을지 고르기. 막힌 곳·망설인 곳을 적는다. 구현 후 2주 동안 위 지표를 파일 메타데이터로 잰다.
- 갈림길 A/B: 오늘 화면에 **메모 입력칸을 직접 둘지(A)** vs 지금처럼 **전역 메모하기 버튼만(B)**. 지금은 B(요소 하나 덜). 2주 써 보고 메모 수가 적으면 A.

## AI 연결 (2026-10-26)

> 앱 주인이 자기 컴퓨터의 pkm-ai-server에 이 기기를 연결하고, pkm이 쓸 AI·모델·생각하는 정도·한도를 정한다. 아직 AI를 쓰는 자동화는 없고, 나중에 `.auto-tag` 자리가 이 연결(`PKMAI.run`)을 쓴다.

**진입점** — 사이드바 저장 위치 줄 바로 아래 `AI · Claude 연결됨`(점 색 + 글자: 연결됨/쉬는 중/서버에 닿지 않음/연결 안 됨), 프로필 창의 저장 위치 줄 아래 같은 글자 + [AI 연결하기]/[AI 설정 바꾸기]. 모바일은 상단 프로필 버튼 → 프로필 창(저장 위치와 같은 길, P8). 탭바·상단바에는 넣지 않았다 — 자주 바꾸는 설정이 아니다(P12). 앱을 열 때 서버에 묻지 않는다(줄은 마지막으로 안 상태, 창을 열면 다시 확인).

**창(`#dlg-ai`, 모바일 바텀시트)**

**시맨틱**: 창 `dialog`(Esc로 닫힘) · 쓸 AI `fieldset`+`legend`+`radio`(화살표 키) · 모델 `select` · 생각하는 정도·한도 `radio` 칩(fieldset/legend) · 도움말 `details` · 사용률 막대는 `aria-hidden`(값은 옆 글자 %가 읽힘) · 저장 알림은 `aria-live` 문단("저장했어요. <상태>") · 오류는 `role=alert` · 다시 그릴 때 포커스를 같은 칸으로 되돌림.

**검증**: 성공 — 연결 코드 붙여 넣기부터 "쓸 수 있어요"까지 한 번에 끝나는 비율(오류로 다시 넣는 횟수 0~1회). 가드레일 — ① 한도를 정한 날 직접 쓰는 Claude가 막히는 일 0 ② "연결됨"인데 실제로 요청이 실패하는 날 수.
