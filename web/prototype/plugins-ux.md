# 플러그인 화면 설계

> 회사 PC에서 토큰을 한 번 넣어 두면, 나한테 온 리뷰와 나한테 할당된 지라 작업을 pkm의 '플러그인' 메뉴 한 곳에서 본다. 지라 작업은 pkm이 PR 직전까지 대신 해 두고, 내가 할 차례에만 나를 부른다. 휴대폰에서는 보고 답하기만 한다.

- 설계 범위: 화면, 흐름, 상태, 카피, 시맨틱. 구현은 메인이 한다.
- 이미 정해진 구조(`docs/PLUGIN.md`, secrets·feeds·run·이 컴퓨터에서 돌리기)는 바꾸지 않았다. 화면이 기대는 규격 몇 가지는 §11에 따로 적었다.
- 예시의 컴퓨터 이름(`회사 맥`), 지라 키(`ABC-123`), 저장소 이름(`web-app`)은 모두 가짜다.

---

## 1. 브리프

| 사용자 | 상황 | 끝낼 일 | 성공 기준 | 제약 |
|---|---|---|---|---|
| 본인 1명(FE 개발자) | 출근해서 회사 맥(넓은 화면)으로 pkm 로컬 서버를 연다. 이동 중에는 휴대폰(390px)으로 같은 데이터를 본다 | ① 나한테 요청된 리뷰, 내 PR의 리뷰 상태, 나한테 달린 답을 한 곳에서 본다 ② 할당된 지라를 PR 직전까지 맡겨 두고 결과만 확인한다 | ① 아침에 리뷰 목록까지 탭 2번 이내 ② 지라 작업이 질문이나 확인이 필요할 때만 나를 부른다 ③ 자동 작업 때문에 내 작업 폴더가 바뀌거나 예상 못 한 지라 전이가 생기는 일이 없다 | 사내 GitHub·지라는 회사 PC에서만 닿는다. 토큰은 그 컴퓨터의 pkm-ai-server에만 둔다. 동기화는 수 분 늦을 수 있다. 공개 저장소이므로 코어에 도메인 말(리뷰, 지라)을 넣지 않는다 |

가정(확인 없이 진행):
- A1. 플러그인 화면은 회사 프로필에서만 쓴다. 개인 프로필에는 플러그인이 없으니 메뉴도 생기지 않는다.
- A2. '업무 시간'은 그 프로필의 하루 설정(하루 시작~끝)을 쓰고, 평일에만 가져온다. 따로 묻지 않는다(P5).
- A3. 기준 브랜치의 기본값은 저장소의 기본 브랜치(origin HEAD)다. 시스템이 알 수 있으니 묻지 않고, 규칙 노트에 적힌 게 있으면 그걸 따른다(P5).
- A4. '작업 폴더 열기'에 쓸 앱은 이 컴퓨터에만 저장하고, 고정 목록(VS Code·Cursor·IntelliJ IDEA·Finder)에서 고른다. 동기화되는 값을 명령으로 실행하면 저장소에 쓸 수 있는 누구나 내 컴퓨터에서 명령을 돌릴 수 있게 되기 때문이다(P11).
- A5. 뒤에서 도는 실행(브라우저를 닫아도 도는 것)에 필요한 pkm-ai-server 연결은 '이 컴퓨터에서 돌리기'를 켤 때 시스템이 알아서 만든다. 가능하면 pkm-app 서버 전용 토큰을 발급한다. 사용자에게 따로 단계를 보이지 않는다.

## 2. 재사용할 것

| 무엇 | 어디 | 이번에 쓰는 곳 |
|---|---|---|
| 하단 탭·사이드 메뉴, 메뉴 편집(`NAV`·`menuItems`·`buildNav`) | index.html `NAV` | 메뉴 '플러그인'. 설치한 플러그인이 있을 때만 생긴다 |
| `page-head`·`h1 tabindex=-1`·`.back`·`.eyebrow` | `vKnowledge`·`vTbBook` | 모든 새 화면 |
| `seg(items, current, cls, pick)`와 휴대폰용 선택 상자 | `seg()` | 플러그인 사이 전환. 마지막으로 본 칸을 기억한다(`kTabStart`와 같은 방식) |
| `section()`·`ul.list > a.row`(title + meta)·`.count`·`.chev` | `vKnowledge` | 피드 항목, 작업 목록 |
| `details.more` 접기 | `vTbBook` | 끝난 작업, 20개 넘는 항목, 실행 기록, 스크립트 내용 |
| `empty(title, body, btn)` | `empty()` | 빈 상태 |
| `.ai-state ok/wait/bad`(굵은 제목 + 본문 + 버튼) | AI 연결 창 | 준비 상태 카드, 작업 상태 카드, 가져오기 오류 |
| `.badge`(`--s-wait`·`--s-review`·`--s-done`·`--danger`) | `statusBadge` | 작업 상태 배지. 항상 글자가 들어간다 |
| `fieldset.choice`(라디오 + 설명) | `dlg-status`·`dlg-sort` | 저장소 고르기, 브랜치가 이미 있을 때 고르기 |
| `fieldset.chips` | AI 연결 창 | 가져오는 주기 |
| `dialog` + `.dlg-actions`([닫기] + 결과 동사) | 모든 대화상자 | 자동 시작 켜기, AI에게 다시 시키기, 그만두기, 플러그인 지우기, 이 컴퓨터로 옮기기 |
| 토스트 + 되돌리기 | `toast(msg, action)` | 자동 시작 끄기, 복사 |
| `.now-links` 텍스트 버튼 줄 | `vNow` 맨 아래 '기다리는 중 N개 ›' | '지금'에서 플러그인으로 가는 줄 |
| `.md` 렌더러(표는 가로 스크롤) | `md()` | AI 보고와 지라 설명 |
| 프로필 창의 한 줄 + 텍스트 버튼 패턴 | `#dlg-profile` | '플러그인 관리하기' 줄 |
| 용어 | 앱 전체 | 상태 이름은 '대기'·'기다림'·'완료'를 그대로 쓴다. 문체는 해요체이고 장식 이모지는 쓰지 않는다 |

새로 만드는 것은 하나뿐이다. **`ol.run-steps`(단계 진행 목록)**. 앱에 단계별 진행을 보여 주는 컴포넌트가 없다. `.ai-steps`는 번호 붙은 안내문이라 상태를 담지 못한다(P8).

## 3. 정보 구조

### 3-1. 어디에 무엇을 두나

| 무엇 | 자리 | 이유 |
|---|---|---|
| 매일 보는 목록(리뷰, 지라 작업) | **새 메뉴 '플러그인'**(`#/plugins`). 플러그인마다 seg 칸이 하나씩 있다. 들어가면 마지막으로 본 칸이 열린다 | 피드는 '지금'(오늘의 시간 블록)과도, '인박스'(내가 담은 메모)와도 성격이 다르다. 그 화면들에 섞으면 각 화면의 One Thing이 깨진다(P3). 메뉴 이름은 사용자가 요청한 말이자 코어가 아는 말인 '플러그인'으로 한다. 코어에 '업무' 같은 도메인 말을 넣지 않는다 |
| 알림 대신 보는 신호 | **'지금' 맨 아래 줄**: `리뷰 · 볼 것 3개 ›`, `지라 작업 · 내 차례 1개 ›` | 기존 '기다리는 중 N개 ›'와 같은 자리, 같은 모양이다(P8). 0개면 그리지 않는다 |
| 설치·지우기·목록 | `#/plugins/_manage`(플러그인 관리). 들어가는 길: 프로필 창의 `플러그인 N개 · 플러그인 관리하기` 줄, 플러그인 화면 머리의 [관리] | 가끔 하는 일이라 메뉴에 두지 않는다(P2) |
| 플러그인 하나의 준비·설정·토큰·돌리는 컴퓨터 | `#/plugins/{id}/setup`(준비와 설정). 플러그인 화면의 [설정]으로 들어간다 | 토큰을 넣고 컴퓨터를 고르는 일은 그 플러그인에 묶여 있다 |
| 지라 작업 하나의 진행·질문·결과 | `#/plugins/{id}/run/{runId}`(작업 화면) | 단계·결과·질문을 담기에 대화상자는 좁다 |

- 메뉴 '플러그인'은 그 프로필에 피드가 있는 플러그인이 하나 이상 설치됐을 때만 `NAV`에 나타난다. 메뉴 편집에서 숨길 수 있다. 처음 생길 때는 설치 완료 토스트로 알린다.
- 하단 탭이 6개가 되면 320px에서 한 칸이 약 52px이다. '플러그인'(12px, 4글자)은 약 48px라 들어간다. 글씨를 200%로 키우면 두 줄로 접혀도 되게 고정 높이를 두지 않는다(P10).
- `_manage`, `_add`는 플러그인 id가 될 수 없는 이름이다(id 규칙상 `_`를 쓸 수 없다). 그래서 플러그인 id와 겹치지 않는다.

### 3-2. 경로

| 경로 | 화면 | 주요 행동 |
|---|---|---|
| `#/plugins` | 마지막으로 본 플러그인 화면. 플러그인이 없으면 관리 화면 | — |
| `#/plugins/{id}` | 플러그인 화면(피드 + 작업 목록) | 항목 열기 / 내 차례 작업 열기 |
| `#/plugins/{id}/run/{runId}` | 작업 화면 | 상태마다 하나(§5-6) |
| `#/plugins/{id}/setup` | 준비와 설정 | 다음으로 채울 준비 항목 하나 |
| `#/plugins/_manage` | 플러그인 관리 | 플러그인 더하기 |
| `#/plugins/_add` | 플러그인 더하기(주소 넣기 → 살펴보기) | 가져와서 살펴보기 → 설치하기 |

### 3-3. '이 컴퓨터'와 '모든 기기'를 화면에서 나눈다

토큰, 스크립트 승인, 작업 폴더 열 앱, 돌리는 컴퓨터 지정은 컴퓨터마다 따로 있다. 설정값, 가져온 목록, 작업 기록은 동기화된다. 이 차이를 문구로 설명하지 않고 **준비와 설정 화면을 '이 컴퓨터' 칸과 '설정' 칸으로 나눠** 구조로 보인다(P2. 설명이 길면 구조가 틀린 것이다). 그러면 "휴대폰에서는 왜 토큰을 못 넣지?"에 화면이 스스로 답한다.

### 3-4. 돌리는 컴퓨터는 플러그인마다 하나다

정책으로 겹침을 없앤다(P12). 이미 다른 컴퓨터가 돌리고 있으면 '켜기'가 아니라 **'이 컴퓨터로 옮기기'** 를 보여 준다. 옮기면 앞 컴퓨터는 다음 동기화 때 스스로 멈춘다. 돌리는 쪽은 작업을 하나 시작하기 전마다 동기화된 `runner` 값을 다시 읽고, 자기가 아니면 시작하지 않는다. 그래서 겹침은 동기화 지연 몇 분 동안에만 생길 수 있다.

## 4. 흐름

### 4-a. 처음 설치 → 토큰 넣기 → 첫 목록

| 단계 | 화면 | 사용자 행동 | 시스템 반응 | 원칙 |
|---|---|---|---|---|
| 1 | 프로필 창 | `플러그인 관리하기` | 관리 화면(빈 상태)을 연다 | P8 |
| 2 | 관리(빈) | [플러그인 더하기] | `_add`로 간다. 주소 칸에 포커스를 둔다 | P4 |
| 3 | 더하기 | git 주소나 폴더 경로를 붙여 넣고 [가져와서 살펴보기] | `https://`로 시작하면 git, `/`나 `~`로 시작하면 로컬 폴더로 알아본다. 고르는 칸은 없다. 400ms가 넘으면 스켈레톤, 3초가 넘으면 `저장소를 받는 중이에요` | P5 Postel, P7 |
| 4 | 살펴보기(같은 화면) | 하는 일, 권한, 스크립트를 읽는다 | 매니페스트를 사람 말로 풀어 보여 준다(§5-2). 규격에 어긋나면 설치 버튼 대신 어긋난 곳 목록을 보여 준다 | P6, P11 |
| 5 | 살펴보기 | [회사 프로필에 설치하기] | 설치하고, 이 컴퓨터의 pkm-ai-server에 스크립트를 승인한다. 이 컴퓨터가 로컬 서버이고 아직 돌리는 컴퓨터가 없으면 이 컴퓨터를 돌리는 컴퓨터로 정한다. 그리고 준비와 설정 화면으로 간다 | P5(시스템이 아는 건 묻지 않는다) |
| 6 | 준비와 설정 | 비어 있는 토큰 칸에 붙여 넣고 [저장하기] | 저장하면 `넣어 둠 · 오늘`로 바뀐다. 준비가 다 되면 **곧바로 첫 가져오기를 시작한다**(따로 누를 필요 없음). 상태 카드가 `준비됐어요`로 바뀌고 [목록 보기]가 나온다 | P7 |
| 7 | 플러그인 화면 | — | 섹션마다 스켈레톤을 보이다가 목록을 채운다. 오류는 그 섹션 자리에 해결 행동과 함께 보인다 | P9 |

- 기존 5단계(관리 → 더하기 → 설치 → 승인 → 돌리기 켜기)를 **4단계로 줄였다**. 승인을 설치에 합쳤고, 돌리는 컴퓨터는 설치한 컴퓨터로 자동으로 정한다. 지라처럼 바깥을 바꾸는 '자동 시작'만 따로 켜게 둔다(4-c).
- 휴대폰(정적 웹)에서는 설치할 수 없다(서버 API가 필요하다). 관리 화면의 [플러그인 더하기] 대신 `플러그인은 컴퓨터에서 pkm을 열었을 때 설치할 수 있어요` 한 줄을 보여 준다.
- 설치한 컴퓨터가 AI(pkm-ai-server)에 연결돼 있지 않으면 설치는 그대로 하고, 승인은 준비 항목 하나로 남긴다.

### 4-b. 리뷰 플러그인 매일 보기

1. 아침에 '지금'을 연다. 맨 아래 `리뷰 · 볼 것 3개 ›`를 누른다. 또는 하단 탭 '플러그인'을 누른다(마지막으로 본 칸이 리뷰라면 바로 열린다). 탭 1~2번이다.
2. 섹션 세 개가 **나를 기다리는 것부터** 차례로 보인다. ① 나한테 요청된 리뷰 ② 나한테 달린 답변 ③ 내가 요청한 리뷰(내 열린 PR).
3. 줄을 누르면 사내 GitHub의 해당 페이지가 새 창으로 열린다. pkm 안에서 하는 일은 없다(P12).
4. 다 보면 다음 가져오기 때 목록에서 저절로 빠진다. 리뷰를 남기면 '요청된 리뷰'에서, 답하면 '달린 답변'에서, 머지하면 '내 PR'에서 빠진다. **읽음 표시나 숨기기 버튼은 두지 않는다.** 목록의 기준을 스크립트(정책)가 쥐게 해서 정리하는 노동을 없앤다(P2·P12).

### 4-c. 지라 작업 플러그인 — 켜기부터 PR 직전까지

**① 설치 직후(자동 시작 꺼짐)**
- 첫 가져오기가 끝나면 지금 할당된 티켓이 전부 '시작 전'에 [시작하기] 버튼과 함께 보인다. 그 위에 한 줄을 둔다. `시작하면 먼저 저장소와 설명을 확인한 뒤, 지라를 '진행 중'으로 바꾸고 브랜치를 만들어요.`
- 처음에는 **하나를 손으로 시작해 보도록** 둔다. 자동 시작 제안은 화면 머리에 조용한 한 줄로만 둔다. 막는 카드를 띄우지 않는다(P6, P11, P16).

**② 자동 시작 켜기**
- 화면 머리의 `새 티켓 자동 시작 · 꺼짐 [켜기]` 또는 준비와 설정의 같은 줄에서 켠다. 켜기 전에 확인창(§5-7 D1)을 띄워 **무엇이 바뀌는지**를 행동 전에 같은 크기로 보여 준다. 지라 상태가 바뀌고, 브랜치와 작업 폴더가 생기고, AI가 커밋한다는 것, 그리고 push와 PR은 하지 않는다는 것이다(P11).
- 켜는 순간 할당돼 있던 티켓은 자동으로 시작하지 않고 '시작 전'에 남는다. 확인창에 개수를 적는다(`지금 할당된 7개는 자동으로 시작하지 않아요`).
- 끌 때는 확인창 없이 바로 끄고, 토스트에 되돌리기를 둔다. 켜는 것보다 끄는 게 쉬워야 한다(P11, P9).

**③ 새 티켓이 할당됨 → 진행**

| 단계 | 바깥을 바꾸나 | 사용자에게 보이는 것 | 막히면 |
|---|---|---|---|
| ① 준비 확인: 저장소 찾기, 기준 브랜치, 브랜치 이름, 지라 설명 | **안 바꾼다** | `1/6 준비 확인` | 내 차례(고르기·적기). 지라는 아직 그대로다 |
| ② 지라 '진행 중'으로 | 지라 | `2/6 지라 진행 중으로` | 멈춤 → [다시 하기] / [상태는 두고 이어 하기](건너뜀) |
| ③ 브랜치 만들기(별도 작업 폴더) | 내 컴퓨터의 git | `3/6 브랜치 만들기` | 멈춤 → 이유와 [다시 하기] |
| ④ AI가 구현하고 커밋 | 작업 폴더만 | `4/6 AI 구현 · 12분째` | 기다림(한도·연결) 또는 내 차례(바꾼 파일 없음, 질문만 남김) |
| ⑤ 결과 점검: 브랜치 규칙, 커밋, push 안 됨, 시험 | 안 바꾼다 | `5/6 결과 점검` | 멈춤 → 어긋난 항목 |
| ⑥ 내 확인 → PR | — | **내 차례** · 요약, 바뀐 파일, 시험, 질문 | — |

- **초안과 다른 점: 묻는 것을 모두 ①로 모았다.** 저장소 선택뿐 아니라 기준 브랜치, 브랜치가 이미 있는지, 지라 설명이 비었는지도 지라를 바꾸기 전에 확인한다. 그래서 질문을 기다리는 동안 지라는 '할 일'에 그대로 있다. 동료가 보기에 '진행 중'인데 아무 일도 안 일어나는 상황을 막는다(P9 실수 예방).
- 별도 작업 폴더(worktree)를 쓰므로 **'저장소에 고치던 파일이 있음'은 문제가 아니다.** 기준은 `origin/{기준 브랜치}`를 fetch해서 잡는다. 화면에 따로 분기를 두지 않고, 자동 시작 확인창의 `지금 작업 중인 폴더는 건드리지 않아요` 한 줄로만 안심시킨다(P2·P15).
- 한 번에 하나씩 차례로 한다. 같은 저장소의 티켓이 여럿이어도 작업 폴더가 따로라 겹치지 않는다. 기다리는 작업은 `차례 기다림 · 앞에 1개`로 보인다.

**④ 질문에 답하기**(데스크톱이든 휴대폰이든 같다)
- '지금'의 `지라 작업 · 내 차례 1개 ›` 또는 플러그인 화면의 '내 차례' → 작업 화면.
- 맨 위 상태 카드에 무엇을 해야 하는지 한 줄, 바로 아래에 답하는 폼이 있다. 저장소는 라디오로 고르고, 질문에는 칸에 적는다. 저장소 답에는 `ABC 프로젝트는 다음에도 이 저장소로` 체크가 기본으로 켜져 있다(P5).
- 보내면, 돌리는 컴퓨터에서는 바로 이어서 한다. 다른 기기에서 보냈으면 `답을 보냈어요. 회사 맥이 받으면 이어서 해요`가 보이고, 동기화되면 상태가 바뀐다.

**⑤ 결과 확인 → 다음 행동**(⑥ 내 확인)
주요 행동은 **진행에 따라 하나씩** 바뀐다. 한 번에 버튼을 다섯 개 늘어놓지 않는다(P3·P4, 목표 기울기).

| 지금 상태 | 주요 버튼(돌리는 컴퓨터) | 보조 |
|---|---|---|
| push 전 | [편집기로 열기] | [push 명령 복사] · [AI에게 다시 시키기] |
| push 감지됨(다음 가져오기 때) | [PR 만들기 페이지 열기] ↗ | [편집기로 열기] |
| PR 감지됨 | 작업이 '끝'으로 옮겨진다. `PR #123을 열었어요` | — |
| 어느 때든 | — | 텍스트 버튼 [끝난 것으로 옮기기] · [그만두기] |

- 다른 기기(휴대폰, 집 맥)에서는 편집기 열기, 복사, PR 열기를 보여 주지 않는다. 그 기기에서는 쓸모가 없거나 닿지 않는다. [AI에게 다시 시키기]와 [그만두기]만 보이고, 요청으로 전달된다.
- push와 PR을 감지하려면 지라 작업 플러그인도 GitHub 토큰이 있어야 한다. 비밀값은 이름 기준으로 컴퓨터에 하나만 두므로 리뷰 플러그인에 넣은 `GITHUB_TOKEN`을 함께 쓴다(§9 결정 4). 감지가 안 되는 환경에서는 [끝난 것으로 옮기기]로 끝낸다.

## 5. 화면 설계

### 5-1. 플러그인 관리 — 목적: 무엇이 설치돼 있고 각각 준비가 됐는지 본다 / 주요 행동: 플러그인 더하기

```
┌────────────────────────────────────┐
│ ‹ 플러그인                          │
│ 플러그인 관리      [플러그인 더하기] │
│ 회사 프로필에 설치한 플러그인이에요  │
│ ┌────────────────────────────────┐ │
│ │ 리뷰                         › │ │
│ │ 0.1.0 · 준비됨 · 회사 맥에서 돌림 │ │
│ ├────────────────────────────────┤ │
│ │ 지라 작업                    › │ │
│ │ 0.1.0 · 준비 1개 남음          │ │
│ └────────────────────────────────┘ │
└────────────────────────────────────┘
```

| 요소 | 내용 | 스펙 | 원칙 |
|---|---|---|---|
| 줄 | `a.row` → `#/plugins/{id}/setup` | meta에는 버전, 상태 하나, 돌리는 컴퓨터. 상태는 우선순위가 높은 하나만 보인다: `바뀐 파일이 있어 멈춤` > `준비 N개 남음` > `준비됨` | P3 |
| 주요 버튼 | 플러그인 더하기 | `btn-primary`. 휴대폰에서는 안내 한 줄로 바뀐다 | P4 |

### 5-2. 플러그인 더하기 → 살펴보기 — 목적: 무엇을 들여오는지 알고 설치한다 / 주요 행동: 가져와서 살펴보기 → 설치하기

```
┌────────────────────────────────────┐
│ ‹ 플러그인 관리                     │
│ 플러그인 더하기                     │
│ 어디서 가져올까요                    │
│ [https://… 또는 /폴더/경로      ]   │
│ ▸ 브랜치나 태그 정하기               │
│           [가져와서 살펴보기]        │
└────────────────────────────────────┘
          ↓ 가져온 뒤 같은 화면
┌────────────────────────────────────┐
│ 지라 작업 0.1.0 · example           │
│ 할당된 지라를 PR 직전까지 작업해요   │
│ ── 하는 일 ──────────────────────  │
│ 가져오는 목록                        │
│ · 나한테 할당된 지라 — 10분마다      │
│ 작업                                │
│ · 지라 작업 6단계 — 시작하기 버튼,   │
│   켜면 자동 시작                     │
│ ── 쓰는 권한 ────────────────────  │
│ ! AI가 파일을 고치고 명령을 실행해요 │
│   (에이전트 · 상한 auto)             │
│ · 비밀값 JIRA_TOKEN · GITHUB_TOKEN      │
│   GITHUB_TOKEN은 넣어 둔 값을 함께 써요 │
│ · 이 컴퓨터에서 실행할 스크립트 3개   │
│   ▸ scripts/assigned.mjs  a1b2c3    │
│ ── 알아 둘 것 ───────────────────  │
│ 가져온 목록과 작업 기록은 회사       │
│ 프로필과 함께 동기화돼요             │
│ [닫기]       [회사 프로필에 설치하기] │
│ 설치하면 위 스크립트를 이 컴퓨터에서 │
│ 실행하는 것도 승인해요               │
└────────────────────────────────────┘
```

| 요소 | 내용 | 스펙 | 원칙 |
|---|---|---|---|
| 주소 칸 | 하나의 칸이 git과 폴더를 모두 받는다 | 레이블은 항상 보인다. 앞뒤 공백과 끝의 `.git`은 받아 준다. `ref`는 `details` 안에 둔다(기본은 비움) | P5, P12 |
| 하는 일 | 매니페스트에서 만든다: feeds의 label과 주기, workflows의 이름·단계 수·시작 방식 | 단계 이름 목록은 `details`로 접는다 | P6 |
| 권한 | 사람 말로 푼다. `agent_mode`가 `read`보다 높으면 맨 위에 `!` 줄을 둔다 | `!` 줄은 `--danger` 글자에 글자 설명까지 붙인다. 색만으로 알리지 않는다 | P11, P10 |
| 비밀값 | 이름(label이 있으면 label). 이 컴퓨터에 같은 이름의 값이 있으면 `넣어 둔 값을 함께 써요` | 다른 플러그인과 같은 값을 쓴다는 사실을 설치 전에 보여 준다 | P11 |
| 스크립트 | 경로, 해시 앞 6자리, 내용(`details` 안의 `pre`, 최대 높이 320px, 넘치면 스크롤) | 이 컴퓨터에 등록해야 하는 `permissions.scripts`는 `이 컴퓨터에 등록해야 해요: jira`로 따로 적는다 | P11 |
| 경고 | inspect `warnings` | 목록 | P9 |
| 같은 id를 다시 설치할 때 | `설치한 0.1.0을 0.2.0으로 바꿔요. 이전 것은 휴지통으로 옮겨요` | 버튼 라벨이 `0.2.0으로 바꾸기`가 된다 | P4 |
| 주요 버튼 | `{프로필} 프로필에 설치하기` | 버튼 아래에 승인 한 줄. 검사에 실패하면 버튼 없이 어긋난 곳 목록과 [다른 주소로 다시 하기] | P4, P9 |

외부 글 규격(매니페스트의 이름·설명): 이름은 1줄이고 40자에서 말줄임한다. 설명은 일반 텍스트로 최대 3줄까지 보이고 나머지는 접는다. 마크다운은 렌더하지 않는다(남이 만든 글이므로 링크나 이미지를 키우지 않는다).

### 5-3. 준비와 설정 — 목적: 이 플러그인이 돌 수 있게 만든다 / 주요 행동: 다음으로 채울 준비 항목 하나

```
┌────────────────────────────────────┐
│ ‹ 리뷰                              │
│ 리뷰 준비와 설정                     │
│ ┌ 준비가 1개 남았어요 ─────────────┐ │
│ │ 사내 GitHub 토큰을 넣어 주세요   │ │
│ └────────────────────────────────┘ │
│ 이 컴퓨터 · 회사 맥 [이름 바꾸기]   │
│ 여기 값은 이 컴퓨터에만 있어요       │
│  스크립트 승인      승인했어요       │
│  AI 연결           연결됨           │
│  사내 GitHub 토큰                   │
│  [••••••••••••      ] [보기]        │
│  repo, read:org 권한이 필요해요      │
│                       [저장하기]     │
│  돌리는 컴퓨터     이 컴퓨터         │
│ 설정 · 모든 기기                     │
│  GitHub 주소 [https://…          ]  │
│  가져오는 때  평일 09:00–19:00       │
│   (하루 설정) [5분][10분][30분]      │
│ 정보                                │
│  0.1.0 · 10월 27일 설치 · 출처 ↗     │
│  [이 플러그인 지우기]                │
└────────────────────────────────────┘
```

| 요소 | 내용 | 스펙 | 원칙 |
|---|---|---|---|
| 상태 카드 | `.ai-state`. 남은 준비 항목 이름을 나열하거나 `준비됐어요 · 회사 맥에서 10분마다 가져와요` | 다 되면 카드 안 버튼이 [목록 보기]가 된다 | P4 |
| 주요 행동 | 준비가 덜 됐으면 첫 번째로 빈 항목에 포커스를 두고, 그 항목의 버튼만 `btn-primary`로 둔다 | 다른 항목의 버튼은 ghost 또는 text | P3 |
| 이 컴퓨터 칸 | 승인, AI 연결, 비밀값, 작업 폴더 열 앱(지라 작업만), 돌리는 컴퓨터, 이 컴퓨터 이름 | 정적 웹(휴대폰)에서는 칸 전체를 한 줄로 바꾼다: `회사 맥에서 돌려요. 토큰과 승인은 그 컴퓨터에서 바꿔요` | P2, 3-3 |
| 비밀값 칸 | `input type=password`, 붙여넣기 허용, [보기] 토글 | 저장하면 칸이 사라지고 `넣어 둠 · 10월 27일 [바꾸기] [지우기]`가 된다. 값은 다시 보여 주지 않는다 | P5(WCAG 3.3.8), P11 |
| 돌리는 컴퓨터 | `이 컴퓨터` / `회사 맥 [이 컴퓨터로 옮기기]` / `아직 없어요 [이 컴퓨터에서 돌리기]` | 옮기기는 확인창 D5 | 3-4 |
| 이 컴퓨터 이름 | 기본값은 호스트 이름에서 만든다. 바꾸기는 그 자리에서 고친다 | 모든 플러그인이 같은 이름을 쓴다(컴퓨터 설정) | P5 |
| 설정 칸 | 매니페스트 `settings`. `type: note`이면 맥락노트 선택 상자 | 바꾸면 바로 저장하고 토스트 `저장했어요`를 띄운다 | P5 회상보다 인식 |
| 가져오는 때 | 하루 설정 시간을 보여 주고 링크로 연결한다. 주기 칩 5·10·30분(기본 10분) | — | P5 |
| 자동 시작(지라 작업만) | `새 티켓 자동 시작 · 꺼짐 [켜기]` | 켜기는 D1. 켜기와 끄기 모두 이 줄 하나에서 한다 | P11 |
| 기억한 답(지라 작업만) | `ABC → web-app [잊기]` 목록. 없으면 그리지 않는다 | 잊기는 바로 하고 토스트 + 되돌리기 | P9 |
| 지우기 | 텍스트 버튼(danger) → D4 | 맨 아래 | P9 |

준비 항목의 상태 문구:

| 항목 | 됨 | 안 됨 | 행동 |
|---|---|---|---|
| 스크립트 승인 | `승인했어요` | `아직 승인하지 않았어요` / `설치 뒤 바뀐 파일이 있어 멈췄어요` | [승인하기] / [바뀐 내용 보고 승인하기](살펴보기 화면의 스크립트 부분을 다시 보여 준다) |
| 등록 스크립트 | `등록했어요` | `jira 스크립트가 이 컴퓨터에 없어요` | [명령 복사] `pkm-ai-server script add jira <경로>` |
| AI 연결 | `연결됨` | `이 컴퓨터의 AI에 연결하지 않았어요` | [AI 연결하기](기존 AI 연결 창) |

**외부 글 규격(AI 보고, 지라 설명, 실행 기록)**. 사례로 삼는 최악의 샘플: 4,000자 보고에 `##` 제목 6개, 표 2개, 코드 블록 5개, 중첩 목록이 들어가고, 마지막 줄이 "I couldn't run tests because…"처럼 영어 실패 문구다. 지라 설명은 비었거나 위키 마크업(`h2.`, `{code}`)이다. 실행 기록은 2만 줄이다.
- **AI 보고는 처음부터 구조로 받는다.** 에이전트에게 `{ summary, questions[], files[], tests }` 형식을 요구하고, 화면은 그 칸을 나눠 그린다. 형식이 깨지면 원문 전체를 아래 규칙대로 그린다(P12. 출처에서 모양을 잡는다).
- `summary`는 `.md` 부분 집합으로 그린다. 문단, 목록(2단계까지), 굵게, 인라인 코드, 링크를 지원한다. `#` 제목은 굵은 문단으로 낮추고, 표는 가로 스크롤 상자에, 코드 블록은 `pre`(최대 높이 240px, 스크롤)에 넣는다. 600자 또는 8줄을 넘으면 앞부분만 보이고 나머지는 `전체 보고 펼치기`로 접는다.
- `questions`는 번호 목록이다. 하나에 300자까지 보이고 넘으면 접는다. 내 차례 상태일 때 질문마다 답 칸이 붙는다(답은 선택. 비워 두면 'AI 판단대로'로 보낸다).
- `files`는 경로(고정폭, `overflow-wrap:anywhere`), 바뀐 종류(`추가`·`수정`·`삭제` 글자), `+n −n`(tabular-nums)을 보여 준다. 15개가 넘으면 `N개 더 보기`로 접는다.
- `tests`는 `12개 통과 · 1개 실패`와 실패한 이름 목록이다. 돌리지 않았으면 `시험을 돌리지 않았어요 — {이유}`.
- 지라 설명은 스크립트가 마크다운으로 바꿔서 준다. 위와 같은 렌더 규칙을 쓰고, `details`로 접혀 있다. 비었으면 `지라 설명이 비어 있어요`.
- 실행 기록은 마지막 200줄만 `pre`(최대 높이 320px)에 보여 주고, 전체는 [전체 기록 복사]로 받는다. 화면에 2만 줄을 그리지 않는다(P7).

## 9. 결정과 근거

1. **새 메뉴 '플러그인' 하나에 seg를 둔다. '지금'에는 개수 줄만 둔다** — P3(지금·인박스의 One Thing)와 P8(seg·now-links 재사용)을 택하고, 탭 수 최소화(P2)는 포기했다. 피드는 매일 열기 때문에 메뉴에 두는 게 맞고, 탭은 메뉴 편집으로 숨길 수 있다. 플러그인마다 메뉴를 만드는 안은 하단 탭이 7개를 넘을 수 있어 버렸다.
2. **'이 컴퓨터' 칸과 '설정' 칸으로 나눈다** — P2(설명 대신 구조). 휴대폰에서 토큰을 못 넣는 이유를 문구로 설명하지 않아도 된다.
3. **돌리는 컴퓨터는 플러그인마다 하나, 켜기 대신 옮기기** — P12(정책으로 겹침 없애기)를 택하고 유연성(두 대 동시)은 포기했다.
4. **비밀값은 이름 기준으로 컴퓨터에 하나만 두고 플러그인끼리 함께 쓴다** — P5(중복 입력 금지)를 택했다. 대신 설치 전 살펴보기에서 `넣어 둔 값을 함께 써요`를 보여 줘 P11을 지킨다. 남이 만든 플러그인이 같은 이름을 선언해 내 토큰을 쓸 수 있다는 위험이 있으므로 그 줄을 권한 칸에 둔다. 플러그인마다 따로 두는 안은 같은 토큰을 두 번 넣게 해서 버렸다.
5. **질문을 모두 ① 준비 확인으로 당긴다(초안 순서 변경)** — P9(실수 예방). 질문을 기다리는 동안 지라가 '진행 중'에 묶이지 않는다.
6. **리뷰 목록에 읽음·숨기기를 두지 않는다** — P12. '나한테 달린 답변'은 '내가 아직 답하지 않은 것'처럼 스크립트가 정의해서 저절로 빠지게 한다. 정리하는 노동이 사라지는 대신 플러그인 스크립트가 더 똑똑해야 한다.
7. **⑥의 주요 행동이 진행에 따라 바뀐다(편집기 → PR 페이지 → 끝)** — P3·P4를 택하고 '모든 행동을 늘 보이기'(P7 숙련자 가속)는 포기했다. 보조 행동은 늘 한 줄 아래에 있다.
8. **수동 시작에는 확인창이 없고, 자동 시작 켜기에만 확인창이 있다** — P9(되돌릴 수 없는 일과 남에게 보이는 반복 효과에만 마찰을 둔다). 수동 시작의 결과는 섹션 위 한 줄로 미리 말한다.
9. **브랜치가 이미 있을 때 기본값은 새 브랜치** — P9(내 커밋 위에 AI가 덧대지 않게). 이어 하기는 한 번 고르면 된다.
10. **외부 글은 출처에서 모양을 잡는다(AI 보고는 구조 JSON, 피드 excerpt는 스크립트가 걷어 냄)** — P12. 화면은 일반 텍스트와 부분 마크다운만 그린다.
11. **화면 정렬과 문구를 코어에 넣지 않는다(섹션 이름, 빈 문구, 정렬은 매니페스트와 스크립트가 정한다)** — 공개 저장소의 '코어에 도메인 없음' 제약. 대신 §11의 표시 규격으로 일관성을 지킨다(P8).

다음 버전으로 미룬 것(P12): 휴대폰 푸시 알림, '새로' 표시, 작업 순서 바꾸기(먼저 하기), push와 PR 자동 만들기, 플러그인 업데이트 확인, 작업 폴더 위치 바꾸기, 피드 항목을 단기로 보내기, 두 컴퓨터에서 나눠 돌리기.

## 10. 검증 계획

- **성공 지표:** 자동·수동으로 시작한 지라 작업 중 **멈춤 없이 '내 확인'까지 간 비율**. 2주 동안 잰다. 목표는 정하지 않고 첫 2주를 기준선으로 삼는다(P16).
- **가드레일:** ① 사용자 작업 폴더가 바뀐 횟수 0 ② 내가 손으로 되돌린 지라 전이 수(그만두기 뒤 '할 일'로 돌린 것) ③ '오래 소식 없음'이 뜬 업무일 수.
- **확인 방법(1인 사용성 과제, 구현 뒤 스크린샷과 함께):**
  1. 처음 설치: 주소를 받은 뒤 3분 안에 리뷰 목록을 본다(막힌 화면을 기록한다).
  2. 휴대폰에서 저장소 고르기 질문에 답하고, 회사 맥에서 이어지는 데 걸린 시간을 잰다.
  3. 처음 여는 사람의 눈으로 라벨만 보고 맞힌다: '시작하기'와 '자동 시작 켜기'의 차이, '다시 하기'와 '다시 시키기'의 차이, '그만두기' 뒤 브랜치와 지라가 어떻게 되는지.

## 11. 화면이 기대는 규격(메인 구현 참고)

화면을 도메인 없이 그리려면 플러그인이 아래 모양으로 값을 줘야 한다. 이미 정한 구조에 이름만 붙인 것이고, 새 기능은 아니다.

- `permissions.secrets`: 문자열, 또는 `{ key, label, hint }`. 화면은 label이 있으면 label을 쓰고 없으면 key를 쓴다.
- `settings[].type`: `text`(기본) | `note`(맥락노트 고르기).
- `feeds[]`: `{ key, label, empty, count: true|false, script }`. `count: true`인 피드의 항목 수가 seg와 '지금' 줄의 '볼 것'이 된다.
- 피드 항목: `{ id, title, url?, meta: [최대 3개], excerpt?, status?: { text, tone: ok|wait|bad }, at }`. 일반 텍스트만 받는다. 순서는 받은 그대로 쓴다.
- 피드 오류: `{ code: auth|network|other, secret?, message? }`. auth일 때 `secret`이 있으면 어느 칸으로 보낼지 안다.
- 작업 단계가 사용자 입력을 원할 때: `{ need: { kind: choose|text|answers, title, options?, remember?: { label } } }`.
- 작업 결과: `{ summary, questions[], files[{ path, change, add, del }], tests{ ran, pass, fail, names[], why? }, branch, path, commits, dirty }`. 이후 가져오기 때 `{ pushed, pr?: { number, url }, pr_new_url? }`.

## 13. 구현과 다른 점 (2026-10-27 첫 구현)

첫 버전에서 줄이거나 바꾼 것이다. 다음 버전 후보로 남긴다.

| 설계 | 구현 | 이유 |
|---|---|---|
| 돌리는 컴퓨터는 플러그인마다 하나 | 프로필마다 하나(`_플러그인/.state/runner.json`) | 한 프로필의 플러그인은 같은 망(회사)에서 돈다. 옮기기·멈추기는 설계대로 |

| ⑥ 편집기로 열기 → PR 페이지 → 끝 | push 명령 복사 · PR 설명 복사 · AI에게 다시 시키기 · 끝난 것으로 옮기기 | 편집기 실행과 push·PR 감지는 다음 버전 |
